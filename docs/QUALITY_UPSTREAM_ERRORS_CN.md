# 质量运维规则的上游错误处理

在「质量运维」新建或编辑规则，打开「上游错误处理」。每一项独立选择「不处理」「暂停凭证」或「移除凭证」。新规则的默认动作是不处理。已保存的规则继续使用各自的动作。保存配置不会发起测试。

| 条件 | 判定依据 |
| --- | --- |
| 401 认证失败 | CPA 对固定凭证发起的探测收到上游 HTTP 401。管理面板自身的鉴权失败仅作为连接错误。 |
| 402 付费要求 | 固定凭证探测收到上游 HTTP 402。 |
| 429 账户配额耗尽 | 上游明确返回可识别的额度耗尽错误，如 `insufficient_quota`。普通 429、每模型限额、每分钟请求数及 token 速率限制均记录调用失败，不触发额度耗尽处置。 |
| 指定模型不支持 | 有两种证据。实际探测收到明确的模型不支持 HTTP 400/404（例如 `model_not_found`），或 CPA 已核实的文件凭证模型目录缺少规则所选模型。后一种在调用前命中，详情显示缺少的模型、目录来源和处置结果。普通参数错误不触发此条件。 |

例如将「401 认证失败」设为「暂停凭证」，其余保持「不处理」，「答错后的处理」也保持仅检测。此时答错只留存判定，401 才会暂停凭证。首个命中已配置动作的样本结束该凭证本次探测，记录包括目标模型、错误条件、执行失败和 CPA 的处置结果。其他凭证继续，同一规则下一轮重新匹配当前目录。无需为已确认的上游处置添加标签或点击人工核对。[检测详情](../artifacts/upstream-errors-0.29.31/ui/upstream-detail.png)

**错误策略成功暂停后退出后续检测。** 401 认证失败、402 付费要求、429 配额耗尽及指定模型不支持（实际 HTTP 返回或可信 CPA 模型目录）都遵循这条规则。从 0.29.36 起，调度直接依据本地已确认的处置记录排除这份凭证，不再读取它的运行状态或快照、不再答题、不重复处置，也不再生成逐轮 `skipped` 记录。首次错误和暂停结果继续可查。答错暂停后的自动恢复不适用于这些错误策略暂停。

本规则原先因答错暂停的凭证，在获准复检时也可能命中配置了处置动作的上游 HTTP 条件。插件将确认的错误原因记入原暂停记录，保持当前停用状态，本轮凭证写入为零，随后退出检测。普通超时和速率限制不产生这类错误策略归属。

错误暂停记录不会因定时发现外部状态变化而自动解除。仅在明确人工处理后，才可结束本地处置关联；日常调度无需人工标记。普通答题质量暂停仍遵守独立的复检配置。[凭证快照与处置归属](QUALITY_CREDENTIAL_ACTIONS_CN.md#归属人工操作与不确定状态)

处置适用于身份和文件快照可核对的 OpenAI / Codex 凭证。0.29.36 起，规则范围决定检测对象，`error`、宿主不可用标记、冷却和缺少模型不再作为排除范围的条件。已启用凭证在有效目录中缺模型时，直接形成「指定模型不支持」检查结果，并执行该项配置；不需要先发出一次必定失败的答题请求。目录检查记录为 `completed`，原因保存在 `preflight_detail`，没有答题样本，不计入已答题数或答题质量通过率。目录证据与真正的上游 HTTP 400/404 分开显示，不伪造 HTTP 响应。

当前 CPA 公开运行状态只提供状态文字、可用性及冷却时间，没有与本轮模型绑定的 HTTP 错误证据。运行异常时继续按当前凭证和规则模型检测，以实际返回确认 401、402、额度 429 或模型 400/404；模型目录未知时也不能直接认定缺模型。管理连接断开、读取失败或身份无法核实时，记录明确的失败或阻塞原因，不误判为上游认证失败。

每次写入前重新检查凭证快照、规则版本与归属，保留写入意图。CPA 写入回执不确定时显示待核对，重启不会重发。官方 CPA 仍有最后一次校验与实际写入之间的并发窗口。

API 使用 `upstream_error_actions` 对象，键为 `unauthorized`、`payment_required`、`quota_exhausted` 和 `model_unsupported`，值为 `observe_only`、`disable_credential` 或 `delete_credential`。编辑时省略对象保留旧配置，显式传空对象清除四项。新增条件不会把 HTTP 错误计为答错。
