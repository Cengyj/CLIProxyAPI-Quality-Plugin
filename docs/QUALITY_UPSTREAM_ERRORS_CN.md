# 质量运维规则的上游错误处理

> 阅读说明（2026-11-21）：答错策略与上游凭证错误策略各自独立。新的人工启用、跨规则错误记录及无标准答案题型要求见 [质量运维逻辑](QUALITY_OPERATIONS_LOGIC_CN.md)，实现差异见 [架构说明](QUALITY_OPERATIONS_ARCHITECTURE_CN.md)。本文仍保留既有实现与验证记录，其中“错误停用后不再核对状态”不是后续目标。

在「质量运维」新建或编辑规则，打开「上游错误处理」。每一项独立选择「不处理」「暂停凭证」或「移除凭证」。从 UI 13.6.59 起，在支持凭证处置的 CPA 上新建规则时，四项均预选「暂停凭证」。编辑已有规则时显示已保存的动作，旧规则中未配置的错误项显示「不处理」。保存配置不会发起测试。

| 条件 | 判定依据 |
| --- | --- |
| 401 认证失败 | CPA 对固定凭证发起的探测收到上游 HTTP 401。管理面板自身的鉴权失败仅作为连接错误。 |
| 402 付费要求 | 固定凭证探测收到上游 HTTP 402。 |
| 429 账户配额耗尽 | 上游明确返回可识别的额度耗尽错误，如 `insufficient_quota`。普通 429、每模型限额、每分钟请求数及 token 速率限制均记录调用失败，不触发额度耗尽处置。 |
| 指定模型不支持 | 有两种证据。实际探测收到明确的模型不支持 HTTP 400/404（例如 `model_not_found`），或 CPA 已核实的文件凭证模型目录缺少规则所选模型。后一种在调用前命中，详情显示缺少的模型、目录来源和处置结果。普通参数错误不触发此条件。 |

例如，若只希望在 401 时暂停凭证，可将「401 认证失败」设为「暂停凭证」，把其余三项设为「不处理」，并为「答错后的处理」选择「仅检测」。此时答错只留存判定，401 才会暂停凭证。首个命中已配置动作的样本结束该凭证本次探测，记录包括目标模型、错误条件、执行失败和 CPA 的处置结果。其他凭证继续，同一规则下一轮重新匹配当前目录。无需为已确认的上游处置添加标签或点击人工核对。[检测详情](../artifacts/upstream-errors-0.29.31/ui/upstream-detail.png)

**错误策略成功暂停后退出后续检测。** 401 认证失败、402 付费要求、429 配额耗尽及指定模型不支持（实际 HTTP 返回或可信 CPA 模型目录）都遵循这条规则。从 0.29.36 起，调度直接依据本地已确认的处置记录排除这份凭证，不再读取它的运行状态或快照、不再答题、不重复处置，也不再生成逐轮 `skipped` 记录。首次错误和暂停结果继续可查。答错暂停后的自动恢复不适用于这些错误策略暂停。

本规则原先因答错暂停的凭证，在获准复检时也可能命中配置了处置动作的上游 HTTP 条件。插件将确认的错误原因记入原暂停记录，保持当前停用状态，本轮凭证写入为零，随后退出检测。普通超时和速率限制不产生这类错误策略归属。

错误暂停记录不会因定时发现外部状态变化而自动解除。完成手动核对或删除所属规则后，插件清理已确认的处置关联。删除规则期间 CPA 的实际凭证或提供商状态保持原样。普通答题质量暂停仍遵守独立的复检配置。[凭证快照与处置归属](QUALITY_CREDENTIAL_ACTIONS_CN.md#归属人工操作与不确定状态)

**在 CPA 重新启用后进行手动智商测试。** 可以在「智商测试」选中该凭证，从当前目录选择模型并点击「开始测试」。插件会重新核对凭证身份、启用状态和所选模型，并在实际调用前再次检查。额度刷新成功只表示额度接口可读。若原处置因缺少模型触发，页面会标出当时缺少的模型。手动测试保留原处置记录，运维规则继续跳过这份凭证。仍被禁用、独立质量暂停、身份不明或处置待核对的凭证无法通过此入口测试。

文件处置适用于身份和文件快照可核对的 OpenAI / Codex 凭证。0.29.36 起，规则范围决定检测对象，`error`、宿主不可用标记、冷却和缺少模型不再作为排除范围的条件。已启用凭证在有效目录中缺模型时，直接形成「指定模型不支持」检查结果，并执行该项配置；不需要先发出一次必定失败的答题请求。目录检查记录为 `completed`，原因保存在 `preflight_detail`，没有答题样本，不计入已答题数或答题质量通过率。目录证据与真正的上游 HTTP 400/404 分开显示，不伪造 HTTP 响应。

当前 CPA 公开运行状态只提供状态文字、可用性及冷却时间，没有与本轮模型绑定的 HTTP 错误证据。运行异常时继续按当前凭证和规则模型检测，以实际返回确认 401、402、额度 429 或模型 400/404；模型目录未知时也不能直接认定缺模型。管理连接断开、读取失败或身份无法核实时，记录明确的失败或阻塞原因，不误判为上游认证失败。

每次写入前重新检查凭证快照、规则版本与归属，保留写入意图。CPA 写入回执不确定时显示待核对，重启不会重发。官方 CPA 仍有最后一次校验与实际写入之间的并发窗口。

API 使用 `upstream_error_actions` 对象，键为 `unauthorized`、`payment_required`、`quota_exhausted` 和 `model_unsupported`，值为 `observe_only`、`disable_credential` 或 `delete_credential`。规则编辑器保存时显式提交四项选择。API 客户端直接新建时省略该对象，表示没有上游错误处置。编辑时省略对象保留旧配置，显式传空对象清除四项。新增条件不会把 HTTP 错误计为答错。

## 额度页与规则记录分别测了什么

CPA 额度页查询账户套餐与配额窗口。Free 和 Business Premium 是套餐名，Codex 窗口的百分比表示剩余额度。额度查询返回 401 说明这次查询的认证失败。窗口剩余 0% 能说明该窗口的额度已用完。

运维记录只展示这一轮取得的证据。规则编辑器预选的模型 ID 可以与凭证在 CPA 实际注册的模型不同。若同一凭证的有效 CPA 目录中缺少所选模型，插件会记录具体的模型名和目录检查结果，并按「指定模型不支持」的策略处理。该次检查没有发出模型请求，所以无法由此知道模型接口会返回何种 HTTP 状态。多个不同套餐或认证状态的账户，可以有相同的目录结果。

实际发起模型请求并收到上游响应时，运行记录才显示该请求取得的 HTTP 证据。401 表示认证失败。429 只有在响应能确认账户配额耗尽时才符合额度暂停条件；单次限速和原因未确认的 429 保留为执行错误。编辑规则和显示记录都不会额外查询账号额度。

## AI 提供商和整轮恢复

13.6.53 起规则分别配置参与检测的对象、检测范围、错误动作与整组启停授权。可信 CPA 模型目录缺项与真实上游错误分别留证。供应商需要核实配置、路由和可验证的请求证据。上游错误暂停可由一条路由的明确证据触发。对于只支持整组停用的供应商，还必须有该组的明确授权。已确认暂停后，保留触发路由、模型、错误原因和处置归属，组内所有模型和路由退出后续规则检测及自动恢复。管理员单独在 CPA 启用该组，原有错误归属仍然有效。手动智商测试可选择身份与配置仍匹配、已在 CPA 启用并注册了所选模型的原生供应商路由。确认路由时接受 CPA 的供应商注册状态（`registered`）。

「全部」可以在保持人工停用期间进行定向检测。开启答错停用和整轮通过后自动恢复，并具备对应处置权限时，才可能从本轮全过的结果启用对象。「仅已启用」的恢复复检仅收录本规则因答错停用且快照和模型集合一致的对象。其他规则的停用、已有独立质量暂停及待核对写入都有各自的阻塞原因。确定的上游错误与调用失败不计作答错。

文件写入沿用 CPA 管理接口的快照复核与写前意图，仍存在非原子窗口。供应商启停采用官方 v8 配置目录的强 ETag 和 If-Match。插件保留未涉及的字段，条件冲突时结束该次写入。只有配置与运行时都确认生效才记录成功。写入回执不确定时保留待核对状态，重启或下一次调度均不重放该写入。
