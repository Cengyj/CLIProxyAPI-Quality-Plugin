# 0.2.0 架构复核：暂停后只等待人工处理

## 本次需求基准

用户已明确选择：**凭证质量暂停后，自动复测和手动复测全部禁止，只允许人工解除。** 这一要求取代 0.1.0 的“暂停中复测、连续通过后恢复”闭环，也取代早期 PROMPT_CN.md、调研文档中相关产品设想。异常判定仍使用完整、可比较的证据与规则阈值；本次没有把默认三轮失败改成单个错误回答即暂停。

## 原实现为什么会继续检测

复核覆盖插件的 `engine.go`、`rules.go`、`reconcile.go`、`store.go`、原生适配与 UI，以及宿主质量权威状态和管理回调。0.1.0 的继续检测来自多处协作，而不是单一按钮：

| 原位置 | 原行为 | 与新需求的冲突 |
|---|---|---|
| `nextRun` | 存在 ActionID 时使用 retest_seconds 计算下次时间 | 已暂停凭证继续进入调度 |
| `execute` | 查找本规则持有动作，构造受限复测授权 | 手动运行规则也可绕过自身暂停 |
| `decideLocked` | 记录连续正确计数并调用 verified recovery | 模型结果能够自动解除限制 |
| `Release` | pause_rule=false 时可继续保留规则启用 | 人工解除后可能立即再次触发旧检测 |
| `Reconcile` | 仅围绕本规则 ActionID 对账 | 无法完整停住其他观察规则、手动任务和作为 control/judge 的依赖 |
| UI/配置 | 暴露复测周期、恢复阈值和自动恢复开关 | 操作语义与“暂停后不再调用”不一致 |

只删除复测按钮或关闭默认自动恢复，不能解决这些路径。旧数据库、已排队任务、热重配和旧版动态库都可能保留原有权限。

## 新的职责划分

宿主继续是凭证限制与身份的权威：保存持久暂停、阻止新业务/评测执行、验证所有权和 CAS，并保留插件不可用时的人工释放入口。宿主扩展升级为 capability v2；旧复测授权和自动恢复回调明确拒绝，不能由旧插件继续使用。

插件负责检测、证据和人工处理流程。运行仍冻结题目、参数、模型、judge 和身份；判定仍区分 execution_status、quality_verdict、action_status。自动化只能从有效失败证据创建暂停，不能从正确答案解除暂停。

规则对外状态为：

| 状态 | 允许的行为 |
|---|---|
| `detecting` | 按启用的调度或显式运行进行检测 |
| `paused` | 规则已停止，等待管理员显式恢复检测 |
| `awaiting_release` | 关联凭证或依赖凭证处于质量暂停/待确认动作，等待人工处理；禁止运行 |

“规则暂停”与“凭证暂停”仍然不同。停止规则不会自行释放凭证限制；人工释放也不会自行恢复规则调度。

## 一次暂停覆盖所有依赖

任务可能将凭证用作被测目标、随机题对照或 LLM judge。凭证暂停必须覆盖这三种角色，而非仅匹配 run.auth_id。

集中暂停转换会持久化依赖规则的停止状态、清零连续证据、取消后续时间并更新 revision；阻止尚未发起的依赖任务，取消插件仍持有的在途评测 operation。业务请求已经通过宿主最终传输准入的部分可自然结束，不因插件暂停强制中断。

准入不只检查一次。提交时检查权威目标状态；worker 获得相关凭证并发锁后重新检查；每次样本/对照/judge 调用前检查任务取消、规则版本和凭证限制。这样，排队期间发生暂停、释放、恢复规则，旧任务也不能作为新一轮检测继续执行。

## 持久化、对账和人工释放

插件 schema2 迁移移除恢复字段的运行意义，保留历史结果和动作归属。旧的 queued/running 运行标记 interrupted，不重发。已经持有暂停的规则及其依赖规则保持停止；旧配置的 automatic_recovery=true 不会重新启用该功能。

跨库仍不是原子事务：先持久化暂停意图和检测停止状态，再向宿主提交幂等动作。host action_status 区分 active、released、absent。对账用于确认归属和修复本地记录，**不发起模型调用，也不重新启用规则**。外部 owner 的暂停同样进入依赖准入检查。

对账核验 owner、规则、凭证、动作版本与身份绑定后才能清除本地归属。存在多个暂停依赖时，按稳定顺序选择仍有效的阻断标记；重复对账不会反复修改版本。解除一个限制不会掩盖其他 owner 或其他 control/judge 依赖的限制。

人工释放始终先停住相关检测、清零连续状态、使旧任务版本失效，再以完整动作绑定 CAS 释放。调用必须来源于活动的鉴权管理请求；后台任务、公共资源和过期管理回调不能获得人工释放权限。释放后的规则仍停止：没有剩余质量限制时为 paused，否则继续 awaiting_release。管理员需要单独点击“恢复检测规则”；恢复时重新检查全部依赖和剩余限制。

## 保留而不扩张的架构

继续使用本地 bbolt、单实例所有权、有界队列和 worker，不引入分布式队列、策略框架或额外状态服务。宿主质量库与插件业务库继续分离。取消、完整上游终止证明、payload 最终屏障、随机题严格对照、日志脱敏与用量来源继续保留。

不再维护复测授权、恢复阈值、连续通过计数和复测调度分支，减少同时影响身份、所有权、调度和网络执行的路径。兼容字段若仍出现在旧 wire 数据中，只用于明确拒绝或迁移，不构成可用能力。

## 本轮执行架构加固

执行核心按职责划分为 `engine.go`（实例生命周期、加载与配置）、`admission.go`（校验、冻结与持久入队）、`scheduler.go`（后台调度及依赖准入）、`execution.go`（模型执行、取消、预算与终态）。规则动作与持久转换仍分别由 `rules.go`、`transitions.go` 管理，没有新增独立执行器或策略框架。

旧 worker 会先取走任务，再等待凭证锁。同一凭证的慢请求可能让全部 worker 都进入等待，使其他独立凭证也无法执行。现在调度器在锁内一次性预留全部主体/control/judge 依赖，只有可运行任务才占 worker；暂不可运行任务继续保持 queued。释放依赖后通过状态广播唤醒，不轮询、不新增网络超时；已取消的队列条目在容量检查前回收。

最终动作判定再次检查所有依赖的可用性与冻结身份，防止最后一次模型调用结束后发生凭证替换或暂停而继续使用旧证据。跨轮签名加入 judge 和 control 身份，因此更换判题凭证不能继续累计旧身份下的失败次数。

停止接单后，规则、人工释放、配置、取消和评审等写入口统一拒绝新变更。并发调用 Close 共同等待首次关闭完成并返回相同结果；未执行任务的 interrupted 状态统一持久化后再关闭存储。原生实例的管理请求租约也与停机分离，避免仍在处理的请求使用已关闭实例。

## 回归验证

需要证明的结果是“暂停后没有额外调用”，而不只是页面显示已暂停。回归测试覆盖：主体/对照/judge 三种依赖，手动/规则/定时入口，排队与取消竞态，旧任务版本，旧配置和数据库迁移，重启/卸载保持，旧复测/恢复 API 拒绝，非管理来源释放拒绝，以及人工释放后规则仍停止。实际原生动态库与浏览器验收记录以本次 TEST_REPORT_CN.md 和 verification 日志为准。

新增调度饥饿、全部依赖一起准入、结束后预留回收、取消任务回收队列容量、判题身份跨轮边界、最终判定前状态变化、停机拒绝变更及重复关闭结果一致性测试，使用明确同步和受控状态，不依赖 time.Sleep。

既有明确限制仍保留：最终可比较自动证据首版仅覆盖原生 OpenAI-compatible chat/completions；Home 动作不支持；停机期间完全相同凭证材料的删除重建无法从现有身份 API 区分；存储阈值是新任务准入上限，不是文件系统硬配额。
