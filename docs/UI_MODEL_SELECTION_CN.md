# UI 4.7.0：模型选择与题目测试布局优化

日期：2026-11-15。目标：依据 sub2api 题目测试源码改善日常使用，解决模型需要手动输入、配置顺序不清和回答区域重复信息的问题。源码研究与参考提交见 [实现研究](SUB2API_UI_RESEARCH_CN.md)。

## 本次变化

- **模型直接选择。** `models` 使用原生下拉，来自鉴权 `/targets` 返回的当前凭证目录。换凭证时保留兼容模型或选择该凭证首个模型；空目录阻止提交并提供配置/刷新指引。后台刷新移除已选模型时保留禁用的旧选择，必须显式重选，避免悄悄换模型。
- **思考强度随模型更新。** 兼容 SDK 的 `Levels`、`ZeroAllowed`、`DynamicAllowed` 和小写形式。未知能力保持默认；能力刷新使旧档位失效时保留草稿并阻止提交。补全宿主已支持的 `max` 档位，插件准入与离线执行测试同步覆盖，未改宿主思考处理或最终载荷规则。
- **配置按任务分组。** 桌面左侧放凭证、模型、思考强度和回答数量，右侧放选题、可编辑题面与重置操作。回答数量改为 1–8 的下拉。有效状态与模型数量收进标签行，异常原因仍完整显示；底部保留开始按钮和调用说明。
- **回答内容优先。** 单模型手动任务在一行概览中集中显示模型、结束进度和不自动评分说明，移除重复模型标题和样本筛选，1–8 份回答直接展示。原始内容、复制、执行详情、HTML/SVG 隔离预览、取消、历史、下载和同配置重跑继续可用；旧多模型记录保留对比与筛选。
- **响应式和状态修补。** 桌面 1280×720 同屏显示配置、主按钮和短回答；手机保留正常滚动及全宽 44px 主按钮。统一任务菜单的 600px 断点，避免 601–760px 时再测试和下载入口不可达。断连清除选中凭证的 title 信息。

没有新增模型探测接口、供应商调用或配置时调用。管理密钥仅保存在页面内存。手动测试不自动暂停；暂停凭证禁止测试、对照或判题；人工解除后规则保持停止。
