# Model Quality 与 CPA 宿主界面的对照分析

调研日期：2026-11-14（Asia/Shanghai）。本轮交付为分析与重构提示词。没有修改 UI、后端、宿主参考源码或运行配置，没有执行模型调用、重跑功能测试或生成发行包。

## 1. 设计判断

建议将设计基准从“只继承 CPA 配色、组件独立设计”调整为“采用 CPA 管理中心的组件语言与页面组织方式”。插件打开后，应当像 CPA 内部的一个功能页面；独立打开时仍能完整使用。

**主要样板选择 CPA 的插件管理页与共享 UI 组件。** 宿主不同功能页存在局部变体，例如凭证库使用墨色胶囊主按钮，配置分区使用 14px 圆角；不宜把所有变体同时搬进插件。基础按钮、卡片、输入、开关、弹窗采用共享组件规范；局部导航参考 ProviderTabs，数据表参考 Table，长表单参考 SectionCard 的分组方法。特殊变体只有在具体任务需要时才引入。

沿用当前“智商测试 / 质量运维”的产品结构。可以重组页面、重做组件和排版，但智商测试仍然是选凭证、选题、编辑题面、选一个模型、获取多份回答的连续流程。

## 4. 两个必须显式解决的内嵌问题

### 主题衔接

宿主 `src/stores/useThemeStore.ts` 在根元素设置 `data-theme="dark"` 或 `"white"`，浅色移除该属性；auto 在系统浅色时解析为 white。`PluginResourcePage.tsx` 直接加载 iframe，没有传递主题。插件现在从 light 启动，仅响应自己的主题 select。

因此，“三套颜色都相似”仍可能出现宿主纯白、插件暖灰，或宿主深色、插件浅色。现有内嵌截图也能看到外壳纯白与内容暖灰的差异。建议同源内嵌时仅跟随父页面公开的 `data-theme`，监听其变化；没有属性映射为 light，white 不得归一成 light。访问失败或独立打开时使用插件自己的三主题选择。不要读取父页认证状态、localStorage 或管理密钥，也不要从宿主复制运行时 CSS。

### 外壳衔接

宿主插件页本身没有常规内容 padding，插件必须负责可用空间与滚动。当前 194px 右侧预留是特定桌面尺寸的处理，不能视为所有侧栏状态、缩放和手机宽度下均成立的布局契约。

建议主内容采用宿主同类页面的标题与间距节奏，并为宿主浮动工具保留经过实际测量的安全区。验证侧栏展开、折叠、窄 iframe、手机以及 200% 缩放。插件不重复绘制 CPA 侧栏或另一组全局工具，连接控件仍明确表示插件自己的管理连接。

## 5. 精确参考不等于复制缺陷

宿主共享主按钮的 `#8b8680` 与白字对比度约 **3.61:1**；当前插件的 `#726d67` 与白字约 **5.12:1**。两者按不透明 sRGB 色对计算，不能据此推断全部状态。普通大小文本需要保留达标的前景/背景组合，可在同一暖灰色阶内调整主按钮，记录偏差原因。

宿主还存在小字号徽章、较复杂弹窗动效等局部选择。可以继承形态和层级，同时保留可读字号、键盘焦点、触屏目标和减少动态效果。商业完成度应由界面一致性与操作可靠性证明。

## 6. 旧提示词中应移除的前提

- “当前 UI 4.0.0、仓库大量文件未跟踪”已不成立；当前有 `82e0b4b` 提交基线。
- “只继承颜色，独立设计组件”被本次用户要求覆盖；不能继续把它当禁止参考宿主组件的规则。
- 手动页不再是配置评测/当前任务/任务历史三个工作台，不应重新加回多模型配置、手动预设、对照和 judge 表单。旧数据读取兼容仍需保留。
- 主题已经使用显式三选项；产品内 action dialog、局部反馈及 DOM 差异更新已经存在，不能把这些再次描述成确定未修复的缺陷。
- `verify_ui.cjs`、`verify_native_ui.cjs` 保留旧 4.1 交互断言，旧 44 项记录不能作为新 UI 的验收基线。当前另有 `test_question_test.mjs`、`verify_question_test.py` 及原生浏览器证据。
- 旧发布包与旧验证记录要按具体版本区分。打包器现在已有源码、产物与证据绑定检查，不能再描述成只有旧 `validated-build.json` 的流程，也不能直接复用 4.1 材料为新 UI 背书。

## 7. 实施顺序与交付建议

1. 固定宿主共享组件与插件管理页样板，完成 token 和组件角色映射。
2. 先处理内嵌外壳与主题，再实现按钮、字段、卡片、Tabs、状态、开关、表格和 dialog。
3. 用新组件重新排版智商测试与质量运维，保持各自产品任务；清理被替代的旧规则。
4. 验证完整流程与所有主题、桌面/手机、独立/内嵌状态，检查回答阅读和轮询期间的交互稳定性。
5. 将最终设计写回设计文档和来源说明，重建并验证动态库，再生成证据一致的本地候选包。
