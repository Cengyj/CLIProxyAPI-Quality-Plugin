# 重置 2FA 卡片：内容梳理与重构方案

> 本文记录 UI 12.2.0 的历史方案。用户随后明确选择「紧凑极简：单栏、少边框、重点突出」，已按该方向全面替换。当前设计见 [UI 12.3.0](UI_REWORK_12_3_0_CN.md)。

## 范围与现状

本轮以 8317 已安装的 UI 12.1.3 为起点，只重构账号行「重置 2FA」确认卡片。参考当前账号页的暖灰、白色、深色主题及圆角、细边框、文字按钮。实现落在 `plugin/ui/`，交付 UI 12.2.0；官方 CPA、账号安全协议和任务执行规则保持原有边界。

当前卡片的主要问题：账号与警告挤在标题区域，两个并排选项视觉权重高于密钥变化；旧密钥失效、新密钥保存和失败后不撤销分散在不同位置；并排选项说明长度不同，图标与勾选框之间留白较多；手机排布与桌面差异大，长邮箱进一步压缩说明空间。

## 内容与实际行为对照

| 用户需要知道什么 | 展示内容 | 实际约束 |
| --- | --- | --- |
| 操作谁 | 完整邮箱，标注「当前账号」 | 依据打开时的账号 ID 和 revision；状态变化后禁止提交 |
| 重置改变什么 | 旧验证器失效，新密钥确认生效后保存到本机 | 新密钥保存先于后续退出/OAuth；不展示真实密钥 |
| 是否退出设备 | 可选「退出所有设备」，说明其他设备需重新登录 | 默认关闭；不是打开页面就执行 |
| 是否同步 CPA | 可选「重新授权 CPA」，说明上传并启用凭证与套餐排除 | 默认开启；已排除的套餐不上传，已确认新密钥仍保存 |
| 失败会怎样 | 结果不明时停止；后续失败不会恢复旧密钥 | 不重放不确定修改，也不增加自动重试 |
| 点击确认做什么 | 根据四种组合生成本次摘要 | 保持原提交接口、幂等和忙碌保护；仅确认按钮提交 |

依据：`plugin/login/security.go`、`plugin/ui/login.js` 和 `docs/OPENAI_ACCOUNT_SECURITY_CN.md`。旧暂停、恢复等历史说明不引入当前确认流程。

## 布局与视觉规范

采用「标题 → 账号与密钥变化 / 后续操作 → 执行摘要与确认」结构。宽屏的左侧集中展示当前账号与密钥变化，右侧使用纵向复选项；只有当前账号和说明使用一块弱底色，选项有一致的行高和文字起点。窄屏的两个主体区域按相同阅读顺序上下排列，旧／新密钥使用紧凑对照，保留 13px 正文。

- 标题 20–22px，选项标题 14px，正文 13px，次级说明最低 12px；正文使用明确行高，邮箱完整换行。
- 主体按 24–28px 留白；组内 8–12px；统一文字起点、线性图标大小和勾选框对齐。
- 沿用现有主题变量。强调色只用于确认动作和旧验证器失效的影响；选中态使用中性色边框、背景及勾选符号，不用绿色成功标记。
- 选项整行可点，键盘空格可切换。仍使用原生 checkbox，不用容易误解为即时保存的开关。
- 底栏显示本次动作顺序，两个选项均取消时显示「仅重置 2FA」。选择不会改变卡片/按钮位置。
- 短窗口滚动内容，保留取消与确认；错误自动滚入视野。首个焦点是取消，关闭后返回原账号行。
- 独立「退出所有设备」保持自身说明、授权选择与提交语义，不显示重置影响。

## 实施与验收

1. 替换上一轮的重置布局规则，减少叠加覆盖；共享的退出设备样式只做必要兼容。
2. 用虚构账号检查暖色、白色、深色、桌面和 320/390px、长邮箱、短高度、四种选择、关闭重开、过期状态及键盘交互；核对前后视觉。
3. 前端回归、插件和运行时测试/构建、未修改宿主基线与必要检查、隔离加载和重启验证。
4. 对既有 8317 实例预检与停服备份，替换已验证插件包；核对原账号/任务/凭证和六份静态资源摘要。
5. 实际官方管理页加载新资源，以临时内存虚构账号截图核验，记录版本、尺寸和验证证据。部署与验证不执行真实重置、退出、登录或模型请求。
