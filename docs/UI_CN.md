# 页面使用与前端验证

本文件描述插件 0.3.1 / UI 4.2.0 的题目测试界面。页面使用原生 HTML、CSS 和 JavaScript ES Modules，通过 `plugin/ui/embed.go` 嵌入动态库，没有前端框架、外部字体、CDN 或分析服务。修改页面后必须重建共享库，单独修改静态源码不会更新 CPA 已加载的插件。

## 两个入口

顶部导航只有“智商测试”和“质量运维”。智商测试提供手动题目测试，质量运维提供独立的规则检测与凭证暂停管理。手动结果不会进入自动暂停判定，不输出通用 IQ 分数，也不提供探针或 ModelTrace。

智商测试页按实际使用顺序排列：测试凭证、题目、可编辑题面和右侧测试选项，下面直接显示本次回答。选项以一个模型、思考强度和回答数量为主，输出上限与 Temperature 放入“输出设置”。结果区只有“本次测试”和“测试记录”，不再要求在配置页与证据工作台之间切换。

质量运维保留“需要关注”“检测规则”“审计记录”三个分区。鉴权连接和浅色、纯白、深色主题选择位于页头；小屏将题面和选项顺序排列。

## 连接 CPA

CPA 中的插件入口为 `/management.html#/plugin-pages/model-quality/0`，也可以直接打开 `/v0/resource/plugins/model-quality/index.html`。公共资源只提供静态页面；凭证、题目、任务、规则、结果和动作通过同源 `/v8/management/plugins/model-quality/` 接口读取或操作。

在“管理连接”输入 CPA 管理密钥。请求使用 `Authorization: Bearer`，沿用宿主的 management 权限与远程访问策略。插件只把密钥保存在页面内存，不写浏览器存储、URL、HTML 或 JSON 导出；刷新、关闭页面或断开连接后需要重新输入。CPA 管理中心与插件的连接分别建立，不通过 URL 向 iframe 注入密钥。

打开页面、连接、刷新、切换题目、编辑题面和保存规则不会调用模型。只有显式开始测试、同配置再测试、立即执行规则或已启用的后台规则调度会提交模型调用。

断连和 401 会清除密钥及页面中的管理数据，旧请求响应不能重填新会话。凭证数据未确认时禁止开始测试。轮询失败保留当前结果并重新读取进度，不重新发送模型请求；刷新不会覆盖尚未提交的自定义题面。

## 题目测试

1. 选择测试凭证。页面显示脱敏 provider、凭证标识和可用状态，不展示邮箱、路径或 token。固定凭证执行，不会自动换号。
2. 选择“糖果逻辑测试”“鹈鹕骑自行车（HTML）”或“自定义题目”。糖果题使用版本化原题；HTML 题要求返回独立页面，以内联 SVG 绘制循环动画。
3. 在题目内容框查看或编辑题面。内置题一经修改即按自定义题提交，不能继续沿用原题答案；页面标示“已修改 · 自定义题目”。同一次测试的每份回答使用相同的冻结题面。
4. 选择或输入一个模型 ID，设置思考强度与 1–8 份回答。模型必须属于所选凭证；思考能力只按宿主已知信息展示，未知不冒充支持。每份回答使用独立会话，回答数量不代表突破宿主或插件的并发限制。
5. 按需展开输出设置，调整输出上限和 Temperature；最终限制还受服务端预算约束。点击“开始测试”后任务先持久化，再由后台执行。

手动页不提供预设、参考答案、跨凭证对照、自动判题或独立 LLM judge 配置。提交明确使用 `judge.mode=manual`；手动 API 未指定判题方式时也默认人工查看回答。内置糖果答案仍可被质量规则的确定性判题使用，但手动题目测试不因此自动评分。

质量暂停、人工禁用和其他原生不可用条件都会阻止新测试。已经质量暂停的凭证不能用于任何复测，也不能用作质量规则的对照或判题凭证；服务端执行同样的限制。

## 看回答与测试记录

点击开始后，在题目下方直接查看进度与各份回答。每份回答保留序号、执行状态、总耗时，以及可取得的 TTFT 和 token 用量。缺失值保持未知，HTTP 成功不代表回答正确。网络、鉴权、限流、截断、拒答和取消分别作为执行情况展示。

文本回答按原文转义显示；可复制回答或打开 HTML / SVG 安全预览。运行中的任务可“停止测试”，关闭页面不会自动取消后台任务。任务结束后可下载脱敏 JSON，或在凭证仍可用时“同配置再测试”；后者是一次明确的新调用，不自动重复未确认完成的旧请求。

“本次测试详情”保留题目版本、冻结题面、模型、参数及执行条件，供需要时检查。`response_model` 只是上游返回标记，不构成模型身份认证。内部 `unknown` 质量结论在手动模式下表示未自动判题，不能据此解释为模型答错。

“测试记录”分页显示历史，打开记录可查看当时的题目与回答。旧版多模型、判题和对照结果继续保留，可按原冻结条件审阅；不将旧记录改写成新手动模式，也不通过简化页面自动重发旧配置。后端旧预设数据与 API 保留兼容，简化页面不再使用它们。

## 质量运维

“需要关注”展示暂停归属、关联规则、动作版本及待处理情况。凭证状态分别列出人工禁用、质量暂停、有效可用性与原因。质量暂停影响整个凭证所有模型的新业务执行；部分模型的证据不等于已经验证凭证所有可用模型。列表缺项不能作为暂停解除或凭证删除的证据。

“检测规则”保留多模型、题目、样本、判题、固定间隔或五段 Cron、时区、预算、失败门槛和保留期。默认只观察；定时检测和自动暂停需要全局与规则分别许可，保存不会立即执行。同一凭证只允许一条自动暂停规则。

默认要求所有选定模型在连续三个完整有效轮次中均明确失败，才允许凭证级暂停。缺样本、unknown、混合结果、基础设施错误、条件或身份变化不构成新的暂停证据。质量通过率以可判定样本为分母，同时展示覆盖率；未知 usage 不当作零成本。

“暂停检测规则”只停止后续检测，不释放凭证暂停。凭证一旦质量暂停，所有依赖该凭证的检测规则和任务都停止，包括作为对照与判题的用途；不提供暂停中复测、自动恢复或复测周期。

“审计记录”保留规则检测、动作意图、暂停、人工解除及冲突记录。底层质量规则的判题配置、旧题目 ID 和持久化状态保持兼容；本轮简化针对手动题目测试流程。

## 人工解除

管理员从暂停归属打开解除预览，先核对凭证、owner、规则、动作版本、凭证身份和剩余限制，再点击“确认解除，保持检测停止”。只释放身份与归属匹配的本次暂停，不解除人工禁用、原生冷却或其他 owner 限制。

解除后相关规则仍停止，旧失败计数清零；必须单独恢复规则才会再次检测。版本或归属冲突需要重新读取当前状态并预览。网络或服务错误造成结果不确定时，使用“刷新并核对状态”，不能把失败响应直接当作宿主没有执行。

宿主持久保存质量暂停，重启、插件停用或卸载不会静默放行。插件不可用时使用宿主管理鉴权保护的查看和人工释放入口；回滚旧宿主前按安装文档处理暂停状态，不能删除数据库。

## HTML / SVG 安全预览

原始回答始终转义，预览在独立 `srcdoc` iframe 中显示。iframe 使用空 `sandbox`、`inert` 和 `tabindex=-1`，不授予脚本、同源、弹窗、表单或顶层导航能力。前置 CSP 使用 `default-src 'none'`，拒绝网络、脚本、子 frame、外部字体和表单，只允许内联样式及 data 图片。

预处理移除脚本、iframe、object、base、meta、link、form、链接和地图元素，删除事件、资源与导航属性，并过滤可以改变资源或导航属性的 SVG 动画。CSS 和 SVG 纯视觉动画可显示；依赖 JavaScript、外部资源或交互的模型输出不会完整运行。安全预览不等于完整浏览器执行结果。预览最多接受 1 MiB 原文，服务端另有响应上限。

## 来源与版本

UI 参考 sub2api 题目测试的使用顺序，以及 CPA 管理前端的配色与交互习惯，页面布局与组件独立实现，不复制参考项目的业务菜单。CPA 固定管理前端参考提交为 `d0126752201a35ff999bd2a1d4741215542258a8`，只读 CPA 8.0.67 源码基线保持不变。

糖果题来源、完整题面版本及 LGPL-3.0 许可记录在 `plugin/NOTICE.md` 和 [源码参考说明](SOURCE_AUDIT_CN.md)。鹈鹕 HTML 题面独立编写。旧 `logic-boxes`、`random-linear`、`visual-pelican` 的版本与内容保留，用于既有规则和历史。

## 构建与本轮验收

静态构建检查 JavaScript，并将资源及 SHA-256 清单输出到 `artifacts/ui/`：

```sh
sh scripts/build_ui.sh
```

插件是独立 module，必须单独验证并实际构建 C shared library。macOS 示例：

```sh
cd plugin
gofmt -w .
go test ./...
go test -race ./...
go build -buildmode=c-shared -o ../artifacts/model-quality.dylib ./cmd/model-quality
```

UI 4.2.0 的验证材料位于 `artifacts/question-test-4.2.0/`。本轮验证使用实际补丁宿主、重建后的动态库、本机 fake upstream 和 CUA 浏览器交互；需检查手动题目、改题、样本数量、取消、结果、历史、安全预览和两个页面入口，并记录对应源码/产物哈希。实际通过项、运行平台及截图见该目录的 `native-api.json`、`browser-verification.json`、`checks.json` 及 [测试报告](TEST_REPORT_CN.md)。常驻本地 CPA 只做安装和页面检查，测试模型调用使用隔离 fake upstream。

本轮可复跑检查：`node scripts/test_question_test.mjs` 与 `python3 scripts/verify_question_test.py`。后者自行启停独立实际宿主和假上游，不接管常驻 CPA。

`scripts/verify_ui.cjs` 与 `scripts/verify_native_ui.cjs` 保留 UI 4.1.0 的旧页面结构和交互断言，不能直接作为 UI 4.2.0 的验收命令。`artifacts/polish-4.1.0/verification-final2/`、`artifacts/terminology-20261114/`、旧精修报告及旧候选包属于历史材料，不能证明新源码已验证。不要把旧报告的通过数量或截图套用到新布局。

可用 `python3 scripts/demo.py start` 创建独立演示，使用返回的 `page_url` 和演示假密钥；结束后运行 `python3 scripts/demo.py stop`。运行配置与隔离边界见 [演示说明](DEMO_CN.md)。本地常驻 CPA 通过 `scripts/local_cpa.sh status|start|stop|restart` 管理，重启保留其专用配置和数据。
