# 质量运维答错处理 · 0.28.0 / UI 13.2.0

## 界面与默认行为

保留 13.1 的单页工作台、规则弹窗和模型编辑器。移除弹窗右上角“仅观察”，在判题设置与运行计划之间增加紧凑的“答错后的处理”：

- 仅检测：默认值，只记录结果。
- 暂停凭证：一轮中全部计划样本完整且可判定，任一模型出现答错后，调用 CPA 原生禁用接口。
- 移除凭证：同样的判定条件，调用 CPA 单文件删除接口；不会自动重新上传。

仅暂停选项下显示“整轮检测通过后自动恢复”，默认关闭。开启后按同一规则、同一模型集合复测，全部模型的全部样本正确才尝试启用。定时仍只有原来一个开关；未开启定时，可通过本规则“立即执行”复测。普通手动测试与人工补充评审不会触发这些处置。

当前自动处理支持可精确识别的 OpenAI / Codex 文件凭证，使用标准答案判题。配置式密钥、运行时凭证、虚拟来源和需特殊路由的凭证不自动处理。全部已启用范围每轮重新匹配；后续新凭证自动纳入，同时纳入本规则持有且已开启恢复的暂停凭证。自动处理要求该凭证匹配全部所选模型，避免只测部分模型就恢复。

“全部凭证”选择“暂停凭证”并勾选“整轮检测通过后自动恢复”时，人工停用的凭证也参加检测。CPA 停用后模型目录为空时，按规则保存的完整模型清单检测。在停用状态下完成全部样本、全部答对且快照仍匹配时启用；部分答对、结果未知或凭证被修改时保持停用。关闭自动恢复时，人工停用的凭证列在本轮跳过清单中。

“全部已启用凭证”排除人工停用的凭证。即使最后一份已启用凭证也被本规则暂停，只要定时和自动恢复均已开启，下一次 Cron 到期仍会复测本规则暂停的凭证。整轮通过且快照仍匹配时恢复，之后继续按原周期巡检。

每次调度为同批到期规则读取一份目录。批量快照读取与模型检测各自遵守插件的 `workers` 上限（默认 2，可配置 1–16），同一凭证在任一时刻仅由一个检测任务执行。同一规则上轮尚在执行或确认处置时跳过重叠周期，下一次到期再匹配。

## 官方 CPA 接口适配

CPA 源码、程序和镜像保持不变。使用现有接口：

- `PATCH /v8/management/credentials/status`：以文件名和 auth_index 禁用或启用。
- `DELETE /v8/management/credentials?name=...`：只删除一个已确认的文件，禁止 all/批量路径。
- `POST /v8/management/requests/api-call`：由 CPA 注入 `$TOKEN$` 并沿用凭证/全局代理。凭证禁用时也可检测，不做“先启用再禁用”。
- 公共 SDK `host.auth.list/get/get_runtime/models`：读取身份、状态与目录；原始凭证只在内存中用于计算摘要与请求所需的非秘密路由信息。

新策略的初测与复测均使用同一管理请求通道，Codex 使用 Responses，OpenAI 使用 Chat Completions；完整响应、终止状态、拒答、用量和错误分别解析。它是受控的管理检测，**不等于 CPA 业务执行链路的模型别名映射、payload rules、thinking 归一化或最终有效参数证明**。原有仅检测与手动测试仍沿用 native model callback。不会把新通道的样本标记为宿主已验证的可比证据。模型 ID 与强度按规则请求发送，服务端拒绝或超时只记未知。

CPA 的 API-call 固定超时约 60 秒，插件本地管理客户端上限 70 秒；长时间思考可能因此得到未知结果，绝不计为答错。该通道不额外实现 Codex OAuth 刷新，凭证过期须先处理授权。

## 归属、人工操作与不确定状态

插件在自己的数据库保存动作意图、规则/运行 ID、凭证摘要、文件名、auth_index、状态与时间。写入意图必须先于 CPA 请求。宿主写入确认后，短暂等待文件监听器同步完成；期间内容或文件时间变化立即转为待核对。后续恢复严格比较整个快照。

检测原先人工停用的凭证时，插件使用本轮开始时的快照，在整轮通过后记录启用意图。已有规则暂停归属的凭证仅由原规则复测；暂停后再次人工禁用、替换凭证、修改文件或身份不一致，都会阻断原快照的恢复。删除会停止依赖该凭证的单目标规则与排队任务；动态范围规则继续处理其他凭证。登录/自动修复提交前检查未解决处置，防止覆盖禁用或重建已移除的凭证。

连接中断、异常响应或无法确认最终状态时记录“待核对”，重试、定时与重启均不会重放该写入。在规则卡片的处置记录中点击“核对人工处理”，会检查凭证已在 CPA 中启用或移除，然后结束本次本地关联并停止规则；此入口不写 CPA 凭证。

从 0.29.21 起，每条规则在本轮所有子任务结束后核对自己的处置标记，空轮次也触发。空闲时没有凭证清理轮询。管理连接有效、凭证已移出目录且 CPA 明确返回文件不存在时，插件才移除对应标记。目录读取失败、文件仍在、同名替换或写入状态不确定时保留标记。单轮跳过答题不能证明凭证已删除。

新规则默认按每个凭证最近 100 条检测结果保留，可设置 1 至 200 条，至少容纳完整一轮。选择“手动清理”后，检测结果一直保存到手动清空或删除规则。删除规则时在同一事务中删除该规则的运行记录、样本和关联日志。历史按天保留的规则仍可沿用原配置。

“质量运维 → 运行记录 → 清空记录”对所有规则生效，包括当前筛选以外的记录。确认后删除已结束的质量检测记录、其中的样本和关联运行日志。排队或执行中的任务、历史独立暂停所需记录、凭证的暂停快照和智商测试历史会保留。删除释放的数据库页可用于后续检测。

**现有 API 不提供对调用者开放的 CAS、独立 owner 或条件删除参数。** 读前核对、写后核对与持久记录可以拦截已观察到的修改，无法消除管理员恰好在最后一次检查与写入之间操作的竞态；不能宣称与宿主原生独立暂停有相同的原子隔离。文件重载或宿主重启后如果时间/身份快照变化，也保守转为人工核对，不推断归属。

历史 `pause_credential`、ActionID 和 BlockedAuthID 原样保留，不能被新策略自动认领或解除。

## 管理连接

后台 API 调用复用经 CPA 鉴权后传入插件的管理请求凭据，只保存在当前进程内存，不写插件数据库、日志或配置。浏览器关闭后本进程的定时任务可继续；CPA/插件重启后，需重新打开已登录的插件面板建立管理连接。连接缺失/失效时停止新处置与管理检测，不自动重试写请求。

本地管理地址默认 `http://127.0.0.1:8317`。其他端口在运行 CPA 的进程环境配置 `MODEL_QUALITY_CPA_URL`，必须使用回环 IP，禁止代理和重定向。容器内填写容器监听端口。
