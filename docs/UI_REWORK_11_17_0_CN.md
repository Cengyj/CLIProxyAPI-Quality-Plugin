## 日志阅读与定位

行内日志改为围绕所选任务展示。顶部显示操作、当前结果、登录方式、触发方式、任务编号、开始时间、最后记录阶段和记录跨度。已确认的安全操作事实只放在任务当前结果中，逐条事件标题不再套用任务最终的 2FA／退出设备状态。

“最近一次”展示账号最新任务；“历史任务”使用带日期、操作、结果和短编号的选择器，一次读取一个所选任务的日志。服务端历史列表最多返回最近 200 次任务，界面明确提示限制；这与每任务保留 200 条事件是两个独立上限。选中的旧任务离开最近列表后仍尝试按编号读取，失败保留已加载内容并提示。

事件以中文阶段和具体原因呈现，时间精确到毫秒，并显示与上一条已记录事件的间隔。搜索覆盖中文内容、阶段、状态和原始错误／原因代码，可与“异常”筛选组合；展开事件可查看固定诊断字段和 JSON。记录跨度是已加载事件首尾时间之差，间隔是相邻事件记录时间差，均不冒充完整任务耗时或阶段处理时间。搜索、展开和手动滚动暂停跟随最新，轮询保留阅读位置与已有内容。

失败摘要把错误代码、停止阶段、具体原因和排查建议分开显示。保存结果未知或安全操作待核对的建议优先于网络重试建议，避免把后续网络失败理解为可以重复重置／退出／导入。

“复制摘要”和“导出 JSON”包含所选任务及其全部已加载事件，不受当前搜索和异常筛选影响。报告包含界面／运行时版本、生成时间与时区、任务编号、固定诊断字段和完整性标记。使用显式字段和类型白名单，不序列化整个 Job，不包含邮箱、密码、2FA 密钥、代理地址、授权 URL、回调或 token。读取未完成、早期记录或截断分别标明；不伪造缺失事件。

## 后端日志元数据

官方鉴权 `/v0/management/plugins/model-quality/login/logs` 增加以下只读字段，无数据库迁移或历史事件重写：

| 字段 | 含义 |
| --- | --- |
| `first_id` / `last_id` | 当前持久化保留窗口的首尾事件序号 |
| `retained_count` | 查询分页前的全部保留事件数 |
| `truncated` | 保留窗口开头是否缺失，与 `legacy` 独立 |
| `has_more` | 当前查询页之后是否还有保留事件 |
| `next_cursor` | 最后一条返回事件序号；空页保留请求 cursor，不回退 |

新记录的 `awaiting_commit + cpa_plan_excluded` 标为提醒，普通等待确认不被标为失败；补齐 `validating` 的信息级别映射。旧事件级别保持原样，原始详情和报告保留其原始级别；界面按错误代码提示并筛选历史信息级事件。日志仍仅投影固定白名单状态／阶段／错误代码，未引入原始上游响应或运行时输出。
