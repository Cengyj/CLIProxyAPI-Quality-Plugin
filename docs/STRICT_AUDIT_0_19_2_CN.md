# 0.19.2 严格审查与优化记录

日期：2026-11-18。基线为插件 0.19.1、UI 12.9.0、Go＋Sobek 2.2.1；本次发布插件 0.19.2、UI 12.9.1，协议运行时仍为 2.2.1。

## 审查范围与当前功能

本轮重新审查插件入口和生命周期、管理接口鉴权边界、账号与凭证存储、登录准入与自动提交、2FA 重置与退出设备、任务恢复、日志持久化、质量观察和前端提交状态。重点以离线故障复现确认缺陷；没有以真实账号操作代替验证。

| 功能 | 当前行为与核对重点 |
| --- | --- |
| 账号管理 | 导入邮箱、密码、2FA 与可选因子绑定，账号资料编辑、代理配置、独立历史和日志；有未确认安全操作时锁定登录、修改与删除 |
| 一键登录 | 账号行登录成功后，经过身份、质量暂停、套餐排除等检查，上传并启用 CPA 凭证；不需要再次候选确认 |
| 自动修复 | 需要全局与账号许可、明确失效证据，执行前及保存前复查策略；不能重新启用后来被禁用的凭证 |
| 重置 2FA | 保持参考项目的因子验证、无旧因子设置、有限冲突处理与确认回执；新密钥和因子保存并读回后，才执行后续操作 |
| 后续选项 | 保留“退出所有设备”“重新授权 CPA”两项；后一项包括上传。退出回执只表示服务器接受请求，不宣称所有会话立即失效 |
| 中断恢复 | 未知远端修改保持隔离，不在重启、巡检或重试时重放；“完成本地保存”只处理已经确认的新密钥，不联网补做其他操作 |
| 模型测试与观察 | 手动测试、历史、规则、取消和预算控制保留；官方宿主不支持独立质量暂停/释放，不用人工禁用模拟，也不清除历史暂停归属 |
| UI | 保留现有主题、54px 双选项、无邮箱行、带边框的执行流程及底部按钮分割线；本次优化异常提交反馈和重复提交保护 |

宿主继续使用未经修改的官方 CPA 8.0.76，业务接口仍经认证通道 `/v0/management/plugins/model-quality/`。管理密钥、账号明文存储等既有用户选择没有迁移。

## 已复现并修复的问题

### 1. P1：账号绑定保存失败后仍可能启动远端任务

原流程先保存任务、启动 goroutine，然后另行保存账号的 LastJobID 和安全隔离状态。两次写入之间存在窗口。离线测试制造账号写入失败后，登录、重置和退出设备均留下孤立任务；重置和退出设备还实际进入了测试运行时。

修复：账号与任务在同一个 bbolt 事务中提交。失败则全部回滚，成功后才发布内存状态和启动 helper。自动修复既有证据消耗规则保持不变。

回归：`TestAccountAdmissionFailureDoesNotPersistOrStartJob`，分别覆盖普通登录、重置及退出设备。修复前后证据见 [失败记录](../artifacts/strict-audit-0.19.2/regression-before.log)、[首次通过记录](../artifacts/strict-audit-0.19.2/regression-after.log)。

### 2. P1：容量不足时提前发布“安全操作已解决”状态

原恢复逻辑直接修改内存任务，再检查存储容量和保存；容量检查失败时，磁盘仍未保存，但内存已经将 SecurityResolved 设为真，使任务隔离判断与持久化证据不一致。

修复：在副本上计算恢复结果；账号和任务共同提交成功后，才发布内存状态。容量失败保持未解决记录并停止服务内后续执行，不发送本地保存确认。

回归：`TestSecurityCapacityFailureKeepsUnresolvedState` 使用临时数据库模拟容量上限，同时检查内存隔离和磁盘证据。

### 3. P2：因子绑定和新密钥保存覆盖任务日志

原 `persistCredentialBinding` 直接覆盖 jobs 记录。内存中的任务没有数据库累计的 LogEntries，因此第一次验证因子、保存新种子或完成恢复时，会清空此前事件并丢失日志版本；复现中最终只剩一条事件且被标为历史不完整日志。

修复：抽出事务内 `saveTx`，所有任务保存统一保留既有事件、日志版本、递增游标和保留窗口。账号、凭证副本及任务仍共用一个事务。

回归：`TestSecurityCommitsPreserveJobLogHistory` 覆盖已验证因子、新种子提交、操作完成及重启读回，检查事件前缀、连续游标和完整性标记。

### 4. P2：本地完成操作无法使用维护预留空间

日志数据库已经接近普通准入上限，但仍有维护预留空间时，`/accounts/security/complete` 被当作新业务准入拒绝，无法完成已确认种子的本地保存。

修复：仅将该明确的离线完成接口加入维护准入。普通登录与远端安全操作仍不能使用维护预留。

回归：`TestSecurityLocalCompletionUsesMaintenanceReserve`；[修复前证据](../artifacts/strict-audit-0.19.2/reserve-before.log)。

### 5. P2：提交响应无法解析时没有进入“结果未确认”保护

原前端只识别网络异常及特定错误码。若服务器可能已接收操作，但响应 JSON 被截断，客户端抛出普通解析异常，重置弹窗不会据此锁定再次提交。

修复：无法解析的写响应明确携带 `outcomeUnknown`，重置弹窗据此禁用提交和功能选项，提示关闭窗口核对账号任务；不自动重放请求。普通读取错误不被当作未知写入。

回归：新增客户端测试，浏览器拦截一次截断 JSON 响应并再次触发表单，验证总请求数不增加。证据见 [客户端修复前失败](../artifacts/strict-audit-0.19.2/frontend-before.log)、[前端测试](../artifacts/strict-audit-0.19.2/frontend-tests.log)、[提交交互报告](../artifacts/strict-audit-0.19.2/browser/security-submit.json)。

## 同步加固与审查结论

- 修正 bbolt `Bucket.ForEach` 回调中写回同一 bucket 的用法。其接口明确禁止遍历中修改；现在先收集变更，再在同一事务内写回。用 150 份合成凭证覆盖相同邮箱、不同种子、其他邮箱和损坏记录，验证匹配更新及全部回滚。此项是接口约束加固，不宣称已复现旧实现丢失特定凭证。
- 更新一条过时的前端测试断言：按当前“服务器接受退出请求、会话失效可能延迟、仅处理后续授权”的准确语义检查，不恢复旧文案。
- 质量执行逐阶段检查、取消传播、官方能力拒绝、保留暂停归属、身份与策略复查以及生命周期租约均纳入现有回归和并发检查。本轮未发现需要据此修改宿主的缺陷。
- 原有历史日志若已经被旧版覆盖，本次无法重建。修复保证之后的因子绑定和种子保存不再覆盖历史事件；部署核对确认当前两条历史任务的现存日志完整保留。
