# OpenAI 网页检查请求与进度修复

2026-11-16；运行时 1.2.1，插件 0.11.2，UI 8.9.2。

## 已确认的缺陷

任务 `89c82772-bb62-4b99-a015-66ee609d8bcc` 在 `session` 与 `browser_verification` 间反复切换，30 秒后报告 `human_verification`。此日志不能证明要求了人工验证码，也不能说明已经提交密码或 TOTP。

使用该账号现有生效代理、完全不提交账号资料的诊断，复现了以下问题：

1. 1.2.0 先打开 ChatGPT 建立网页会话，但请求策略只允许授权站点和 Cloudflare 域名的检查 POST，遗漏 ChatGPT 自身 `/cdn-cgi/challenge-platform/`。修复前观察到八次该类 XHR POST 被本地拦截。
2. 页面重载期间，标题和正文会暂时为空。旧检查将其当成已经通过验证，恢复 `session`，甚至可能提前开始下一步 API 请求。
3. 自动检查持续 30 秒后，旧检查直接报告 `human_verification`。没有记录到人工提示也会使用该原因。

证据保存在 `artifacts/login-verification-1.2.1/session-before.json`。诊断只记录来源、规范化路径、方法、状态和固定页面标志，没有保存请求头、查询参数、Cookie、账号资料或验证码。

## 修复行为

- 仅允许官方 ChatGPT/授权来源、验证目录下、非导航的 POST fetch/XHR 检查；其他写入和账号创建、改密、MFA 设置仍不支持。
- 页面标题、正文和就绪状态在同一次读取中取得。空白、导航异常与读取失败不构成通过证据；必须看到稳定可读的正常页面后才推进。
- 检查期间保留同一等待预算和恢复阶段。过渡页面不会重置计时，也不会反复发布 `session`。
- `browser_verification_timeout` 表示自动检查超时；`browser_verification_required` 表示 API 返回了检查页面；只有明确人工操作提示才报告 `human_verification`。宿主任务、持久化日志和 UI 保留同一分类。
- 继续使用官方页面自身的检查脚本，不生成或填写验证答案。

修复后使用相同代理的无凭证观察已确认：ChatGPT 检查 POST 与 Cloudflare 检查 POST 正常发出，收到 HTTP 200，且不再在空白页恢复 `session`。检查请求返回 200 并不代表账号已经登录成功。

## 验证范围

离线双来源夹具覆盖 ChatGPT 同源 fetch/XHR 检查后完成密码、MFA 和宿主 OAuth，导航中空白页面，禁止的 PUT/导航 POST/目录外写入，以及自动超时、人工提示和 API 检查响应的分类。宿主测试覆盖运行时 1.2.1 接纳、错误映射与日志持久化；UI 检查覆盖三类原因和提示。

构建、安装、真实网站观察和账号尝试证据统一保存在 `artifacts/login-verification-1.2.1/`。真实登录只有取得并核验候选凭证才能认定完成；离线夹具通过或检查接口返回 200 均不能代替此条件。
