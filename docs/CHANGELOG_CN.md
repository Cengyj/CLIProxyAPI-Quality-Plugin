# 版本变更

## 0.3.0：架构加固与独立质量控制台界面

保留“质量暂停后全部禁测、仅人工解除”的产品规则，收敛执行、调度、查询和实例生命周期的职责。

- worker 只领取全部凭证依赖均可执行的任务，避免同一慢凭证占满 worker；取消任务立即回收入队容量。
- 定时 tick 绑定捕获的规则版本，入队前重新检查定时开关；编辑规则和关闭调度不会被旧 tick 触发新执行。
- 最终动作前重新检查目标、control、judge 状态与身份；连续证据签名加入判题与对照身份边界。
- 关闭与持久化故障统一阻止写操作；并发关闭共享完成结果，原生实例使用请求租约协调重配和停机。
- 预算按调用准入 UTC 日期记账，跨日迟到用量不污染新日额度；按保留期清理且保护在途日期，token 累计防溢出。
- 明确类型的深复制替代 JSON 编解码复制；运行查询先分页后复制，指标与审计读取失败明确报错。
- API 错误按实际冲突、限制与服务不可用分类，保留未知值和执行/质量/动作状态的区别。
- 两页采用独立的雾蓝/深蓝与青绿色质量信号主题；窄图标工作区轨道、顶部上下文导航、结果观察台与配置侧栏重新组织信息层级。CPA 管理中心只作为信息密度参考，不复用其页面或组件。会话断连清空管理数据，过期响应不会覆盖新视图，轮询错误只重试读取，不重复提交任务。
- 原生RPC保留HTTP状态，统一静态资源与业务路由；异常流清理、预取消和完成竞态有明确终态。

继续使用数据库 schema2 和宿主 quality capability v2；不重新引入复测或自动恢复。具体安装与回滚要求见 INSTALL_CN.md，验证记录见 TEST_REPORT_CN.md。

## 0.2.0：暂停后只允许人工解除

本版本按用户确认的新产品逻辑调整架构：确认质量异常并暂停凭证后，全部停止复测，不再自动恢复。管理员必须先人工解除相应暂停，再单独恢复检测规则，才能开始新的检测。

- 移除插件复测执行、复测周期、恢复阈值、连续通过计数和自动恢复配置的运行路径。
- 统一处理被测目标、随机题对照和 judge 依赖；暂停阻止相关手动任务、规则任务和定时任务。
- 规则状态明确为 detecting、paused、awaiting_release，人工释放后保持 paused。
- 宿主能力升级为 v2，旧版复测授权和 verified recovery 回调明确拒绝。人工释放要求鉴权管理请求作用域。
- schema2 迁移保留历史、预算和暂停归属，旧恢复设置不再生效；未完成旧任务标记 interrupted，不重发。
- 继续保留真实凭证级限制、身份与动作 CAS、重启/卸载持久化、严格证据和手动测试功能。

异常暂停默认门槛仍为所选模型全部明确失败的连续三轮。手动测试仍不触发自动处置；“发现异常并已暂停后不复测”不等于“任意一次错误立即暂停”。

升级要求和旧宿主回滚流程见 INSTALL_CN.md。不要用旧 0.1.0 动态库替换新库来获得复测功能；新的宿主契约会拒绝旧授权。迁移前备份两个数据库，不删除暂停状态。

## 0.1.0：历史版本

完成手动测试、质量规则、原生插件、暂停中受限复测与自动恢复的原始实现。其复测与恢复行为已被 0.2.0 的新需求取代；旧验证材料仅作为历史记录，不代表当前产品能力。
