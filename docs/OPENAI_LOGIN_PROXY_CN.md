## 代理设置

登录代理独立于 CPA 业务请求的代理配置。它同时用于插件启动的密码与 TOTP 登录和后续授权码兑换。官方插件当前的选择顺序为：

1. 本次登录请求或账号指定代理。
2. 登录设置中的默认代理。
3. 重授权目标凭证原有代理。
4. 直连。

当前官方插件入口没有从 SDK 获取 CPA 全局代理，不应依赖全局代理自动继承；需要统一出口时，在插件“代理与巡检”中保存默认登录代理。

留空表示沿用下一层设置；`direct` 表示明确直连。配置在任务创建时确定，不会因任务执行期间修改设置而中途切换出口。已打开的官方浏览器授权窗口使用操作者浏览器自己的网络设置，宿主代理不能替它配置浏览器。

账号代理、默认登录代理以明文保存在插件自己的账号数据库中，不需要加密密钥。批量导入可为本批账号设置代理，账号资料可单独覆盖。代理设置不会改变已经绑定的 CPA 凭证的业务代理，不会自动发起登录或模型请求。

原生引擎支持 HTTP、HTTPS、SOCKS5、SOCKS5H。Go/Sobek 2.1.1 保留 SOCKS5H scheme，使密码/TOTP 登录继续由代理解析目标域名；SOCKS5 使用本机解析。此前适配层错误地把 SOCKS5H 改成 SOCKS5，导致远端 DNS 设置丢失。当前未采用浏览器传输，不适用旧 Chromium 的 SOCKS 限制。

新任务通过固定诊断代码区分代理认证拒绝、代理 DNS、连接拒绝、超时及 TLS 错误。容器中 `127.0.0.1` 或 `localhost` 指容器本身；如代理运行在宿主机，应使用容器可访问的地址，例如 Docker Desktop 的 `host.docker.internal`，并确认代理监听地址允许该连接。插件不会自动重写已保存的代理配置。旧任务保留原有诊断，不补造历史原因。
