## 3. 优先处理当前可见问题

下列线索来自本次调研；实施前重新核对是否仍存在。按影响处理，不能仅修几个 CSS 数值就结束。

### A. 调整首屏节奏与工作区密度

当前主导航、数据新鲜度、全局通知、页面标题、局部导航、结果标题、运行摘要和比较筛选连续占据纵向空间。比较截图中，回答正文出现较晚；手机端同样需要经过较长的说明区。

- 合理合并同层信息，缩短重复说明，明确标题、任务状态、操作和证据各自的层级。
- 在常规 1440×900 桌面视口，进入已完成任务时应能理解任务身份、切换比较对象并看到回答正文开头。核查实际视图切换后的滚动位置，不只检查全页截图。
- 手机端突出当前任务、状态与下一个动作，减少重复导航和提示占位。不要靠缩小正文和点击区域压缩空间。
- 必要时采用局部吸附的比较工具或操作区；必须处理焦点、软键盘、底部安全区域和遮挡，避免每层都吸顶。
- 正常、无待处理事项的运维页面应简洁；关键暂停与阻断信息保持醒目。

### B. 做细排版、对齐与组件质感

- 统一同角色的字号、字重、行高、间距、边框和圆角；兼顾数学对齐与视觉对齐。
- 当前 11px 状态标签和大量 12px 说明需要逐项判断。关键状态、操作和解释不能依靠细小文字承载；次要元数据可保持紧凑。
- 为中文说明、自然语言回答、代码/HTML/SVG 原文分别安排合适的字体和行长。不要将所有回答无差别当代码阅读，也不要修改模型原文；复制与导出保留原始内容。
- 数字、百分比、token、耗时和日期使用一致格式；数据比较采用等宽数字。缺失值与真实零值明确区分。
- 用工作面、留白、边界和字重建立精致感。图标只用于识别与动作，统一尺寸、线宽和光学基线。
- 控件覆盖 default、hover、focus、active、disabled、busy、error；焦点与错误不能造成混淆，加载时按钮宽度保持稳定。
- 保留 CPA 色系和既有对比度改进。浅色、纯白和深色都独立检查，避免某一主题只是变量替换后未经查看。

### C. 统一反馈和操作组件

当前 `app.js` 的 `notice()` 将反馈放入全局条幅，页面切换不清理；现有比较截图仍显示此前解除操作的消息。预设命名使用浏览器 `prompt()`，规则删除使用 `confirm()`，主题通过一个文字按钮循环三个状态。

- 为消息定义作用范围和生命周期。复制成功在对应按钮附近反馈；保存成功关联具体对象；普通成功反馈短暂且可访问。连接失效、数据陈旧、解除结果不确定等重要状态持续保留在合适位置。
- 页面切换后，局部操作消息不能冒充新工作区的当前状态；真正全局的连接状态继续可见。
- 将预设命名与规则删除整理为统一的产品内交互。简单输入可用轻量原生 dialog；危险动作明确对象及后果，不伪造后端不存在的撤销能力。
- 主题选择明确展示浅色、纯白、深色和当前选中项，使用适当的原生选择或可访问菜单；不扩大到未经要求的宿主同步或存储方案。
- 处理中的动作显示实际进度语义，例如“保存中”“读取状态中”。区分没有数据、尚未加载、加载失败和暂无匹配结果。
- 字段错误靠近字段，正确关联标签和帮助；提交失败保留输入并把焦点带到合理位置。

### D. 打磨回答比较与证据阅读

- 同编号样本、模型标题和关键状态对齐；避免为一个很短的回答预留过大空白，也避免一侧长内容让另一侧操作漂得过远。
- 两边显示同一组状态角色，但执行状态、质量结论和可比较性始终独立。避免全都使用同样强度的彩色标签。
- 长模型名提供可辨认的完整信息，选择器不能只剩无法区分的相同前缀；完整 ID 可查看、可复制。
- 优化长回答的展开、收起、内部滚动与页面滚动，手机上始终能确认正在看哪个模型与样本。
- 证据详情先给出判定与可比较性摘要，再给模型路径、条件和用量。身份指纹和原始 JSON 保留在诊断层。
- 已知稳定状态码与错误原因使用准确中文说明；例如当前可见的 `manual_test`、`exact answer` 等内部表达应按明确映射处理。原始诊断信息保留，未知错误不得擅自解释为某种质量结论。
- 只通过已有安全隔离机制展示 HTML/SVG，保留原文转义、空 sandbox、inert、严格 CSP 以及脚本、网络、表单和导航封锁。排版升级不能引入执行模型内容或外部请求的通路。

### E. 保证长任务中的交互稳定

当前 `renderRun()` 会整体重建样本 DOM，再恢复部分评审草稿。需验证它对正在操作的用户是否产生影响，不能未经测试宣称已有数据丢失。

- 用可控 fake 轮询验证：焦点、文本选择、输出内部滚动、长回答展开、评审折叠状态、未保存备注和比较筛选能否保持。
- 确有问题时在合适层级修正渲染与状态保存，避免轮询闪烁、焦点跳走或用户输入被覆盖。
- 当前任务的临时状态不能串到另一任务或新连接；断开、401、切换凭证身份后按既有边界清理。
- 规则/预算编辑需要清晰的未保存状态。关闭或切换导致真实草稿丢失时提供合理保护，不对每次普通导航弹确认。
- 对实际支持的最大模型数、样本数、输出长度及分页内容做压力检查。只在有证据时引入优化，不添加无需求的缓存或复杂框架。

### F. 完善移动端和无障碍细节

- 在 360/390px 手机、768/1024px 中间宽度和 1280/1440px 桌面检查关键流程；选择代表状态覆盖，不机械穷举所有组合。
- 手机输入控件字号至少 16px，避免 iOS 聚焦自动放大；主要触控目标建议至少 44×44px。
- 核查表格转列表、证据字段、预算网格、长标识和多按钮换行；不要仅靠 `overflow-x: hidden` 掩盖溢出。
- 检查 200% 缩放、键盘顺序、焦点归还、Escape、表单标签、菜单语义、动态状态播报和 reduced-motion。
- 以 WCAG 2.2 AA 适用项为验收目标：普通文本至少 4.5:1，大字及必要控件边界/焦点至少 3:1。逐项提供证据，不能把颜色抽样或自动扫描当作整站认证。
- 验证 CSS subgrid 等关键布局能力在目标浏览器的实际表现。未测试的浏览器/设备如实记录，不声称已支持。

## 4. 产品与工程边界

以下语义与能力不因精修而改变：

- 手动评测不自动处置；打开页面、连接、保存配置/预设/规则不调用模型。
- 质量暂停覆盖整个凭证所有模型的新业务执行。暂停凭证不能作为目标、对照或判题凭证参与评测。
- 不提供暂停中复测、绕过权限或自动恢复。
- 人工解除只释放匹配身份、归属和版本的暂停；相关规则仍停止，旧计数清零，恢复检测须独立显式操作。
- 人工禁用、原生冷却和其他 owner 限制分别保留。
- 只有完整、可比较、明确错误的证据推进失败判定。基础设施错误、取消、拒答、截断与 unknown 不算答错。
- 管理密钥只在内存；同源鉴权 v8 API、迟到响应隔离、防重提交、取消链路、断连/401 清理继续有效。
- 维持原生 HTML/CSS/ES Modules 与 Go 嵌入方式。不新增运行时 CDN、远程字体、分析服务或框架构建链。
- 合理拆分前端模块时，同步修改静态嵌入、构建清单和验证。维持英文代码注释，新中文文档使用 `_CN.md` 后缀。
