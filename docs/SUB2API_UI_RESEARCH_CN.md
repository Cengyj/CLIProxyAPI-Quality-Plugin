# sub2api 题目测试实现与本插件界面改进依据

核查日期：2026-11-15。参考仓库：[ranxi2001/sub2api](https://github.com/ranxi2001/sub2api/)。本次实际阅读的是 `workspaces/sub2api/` 中未修改的提交 `ccf997c73868083d96c0bec56e71c1a34d26c98a`（提交标题 `chore: sync VERSION to 2.21.2 [skip ci]`，提交时间 2026-11-13 10:05:48 UTC），没有切换或更新参考工作树。本次远程 HEAD 查询未完成，不能把本报告称为最新远程版本核查；既有 [题目测试对照](SUB2API_QUESTION_TEST_CN.md) 另记录过 2026-11-15 对远程提交 `e90811e27bc442763a496027f935a7bb1fb4396b` 的比较。本报告是源码调查，界面验收另以本次实际浏览器结果为准。

## 核心结论

sub2api 的题目测试是一个清晰的操作链：**已选账号 → 选题并编辑题面 → 从账号目录选模型 → 调整思考强度与回答份数 → 开始 → 逐份阅读、预览和下载**。其模型控件默认是可搜索的下拉选择，手动输入是额外入口。本插件已有凭证模型目录与推理能力数据，正常流程却使用 `input + datalist`，使“选择模型”看起来像填写模型 ID。这是前端交互问题，不是缺少后端模型接口。

应优先把凭证与模型放在同一组，把模型改为明确的目录选择；选择凭证后即可看到可用模型，换凭证时重新校验选择。题面保持主要阅读面积，回答数量与思考强度收在次要选项组。回答区以内容为主，单模型手动测试不应展示无用的模型对比控件。历史、冻结条件和诊断信息保留，但不与开始测试争夺首屏空间。

## 题目、判定与预览的边界

糖果题的完整题面与数表在 `frontend/src/utils/intelligenceTest.ts:4`，交付要求仅输出最终整数。鹈鹕题在 `:8`，交付要求独立 HTML、无 Markdown 围栏、无外部依赖。手动逻辑题的 `success` 表示生成流程完成且有文本，**没有把答案是否为 21 作为成功条件**；HTML 提取成功也不能证明画面正确。测试不产生经过校准的 IQ 分数。

`frontend/src/utils/pelicanHtml.ts:23` 兼容代码围栏、完整 HTML、裸 SVG，并通过前置 CSP 阻止外部资源及网络。原版 iframe 使用 `sandbox="allow-scripts"`，可执行内联动画脚本（`IQTestModal.vue:263`）。本插件明确禁止脚本、外部网络、导航及表单，不应为了复刻预览而放宽已有边界；继续提供转义原文与隔离预览即可。

随机 HTML 题是另一个完整子流程：`frontend/src/utils/pelicanQuestionRound.ts:5` 保存同一标签页内、同一管理员的题目轮次；准备题目只取快照，不调用模型。不能只加一个“随机题”按钮而省略快照、版本和跨账号比较条件。本次布局优化无须移植这个额外系统。

## 本插件已有能力和当前障碍

以下是开始本次改版前的源码定位；后续实施可能移动行号。

| 问题或能力 | 证据与影响 |
| --- | --- |
| 模型已有数据 | 宿主 `workspaces/CLIProxyAPI/internal/pluginhost/quality_callbacks.go:112`–`:125` 生成 `models` 和逐模型 `reasoning`；插件 `plugin/quality/host.go:51` 获取 `host.quality.targets`。无需让浏览器调用供应商或引入新模型探测。 |
| 输入框掩盖选择能力 | `plugin/ui/index.html:39` 是 `input list="model-options"`；`plugin/ui/app.js:464` 只填 datalist。浏览器是否显示候选与输入内容、控件实现有关，不能保证用户一眼看到目录。 |
| 服务端拒绝任意模型 | `plugin/quality/admission.go:158` 对每个模型检查 `target.Models`，不在目录就拒绝；因此自由输入并不是后端支持的探索通道。 |
| 能力键名需要注意 | `sdk/pluginapi/types.go:223` 的 `ThinkingSupport` 没有 JSON tags，实际为 `Levels`、`ZeroAllowed`、`DynamicAllowed`、`Min`、`Max`；插件 `Target.Reasoning` 原样保留。新 UI 应兼容大小写，不能只读取小写 `levels`。 |
| 思考强度尚未利用能力 | 改版前 `plugin/ui/index.html:42` 固定提供默认、none、low、medium、high、xhigh，没有随着所选模型变化。未知能力应保持默认，不应凭猜测提供全部档位。 |
| 手动测试只选一个模型 | `plugin/ui/app.js:498` 的手动配置已约束单模型；多模型对比控件对这类新任务无意义，可按结果类型隐藏，仍保留旧记录和规则运行的比较能力。 |
| 手动结果重复信息较多 | `plugin/ui/view.js:305`–`:369` 每个模型标题及每张样本卡重复模型 ID，且短回答也带完整元数据行和多个操作。模型/题目/份数可集中在轮次摘要，样本卡突出编号、状态、正文和必要操作。 |
| 关键安全语义已存在 | 手动测试不自动评分或暂停；质量暂停禁止所有复测；人工解除后规则仍停止。这些约束应保持，仅将重复说明下沉到对应操作或详情。 |

## 建议采用的布局与交互

1. **按决策顺序组织配置。** 凭证与模型相邻；选择凭证后马上显示目录中的模型。题目选择紧邻题面；思考强度和回答份数放在同一选项组。开始按钮固定在配置末尾，窄屏使用清晰的全宽主按钮。
2. **模型必须可直接选。** 使用真正的下拉；目录较多时提供搜索。刷新时保留仍然有效的选择，换凭证时若旧模型不适用则选择新目录的可用项或要求重选；空目录、读取失败和未选凭证分别说明。没有可用模型时禁止提交，不能以手输掩盖故障。
3. **思考档来自已知能力。** 始终提供“默认”；只列当前模型声明的支持档，切模型时重置无效档。能力未知显示简短解释，不承诺支持；不要复制原版前端的低/中/高错误回退。
4. **降低无效首屏占用。** 减少重复身份横条、模型标题、未开始时的多层空状态和总是展开的次要动作。保留可读字号、明确标签、合适点击面积和手机自然流布局，不能靠压缩文字或多层嵌套滚动换取首屏高度。
5. **回答内容优先。** 简单手动测试显示轮次摘要和每份回答；单份与多份用不同密度。复制、预览、执行详情保持就近可达，历史和冻结条件为次级入口；长文本局部展开且不丢编辑草稿。
6. **联动状态要完整。** 测试中显示进度和停止；断连、陈旧凭证状态、人工禁用、质量暂停分别阻止执行并说明原因。刷新目录不得覆盖用户正在编辑的题面。

## 不直接照搬的部分

- 不引入原版探针、ModelTrace、定时测试第三套导航，现有“智商测试 / 质量运维”已经覆盖当前范围。
- 不硬编码 GPT/Claude 型号。目录应以当前宿主凭证能力为准。
- 不照搬手输任意模型、未知能力低/中/高回退，因本插件准入和可比较性要求不同。
- 不把“回答数量”改叫“并行数”。本插件同任务逐份执行，选 8 份不等于同时发 8 次调用。
- 不把参考项目保存在 `localStorage` 的认证方式带入插件；本插件管理密钥仍只在内存。
- 不通过生成成功推导答对、降智、凭证可用或任何暂停动作。
- 不改变输出预算、固定凭证执行、最终载荷屏障、所有权、禁止复测和仅人工解除等后端语义。

## 实施后应验证的重点

使用离线凭证与假上游验证：不输入模型 ID 即可完成测试；不同凭证目录切换、空目录、目录变化、长模型名、推理能力未知/有限档位均正常；刷新不会覆盖草稿或合法选择；1/多份回答、停止、历史重跑与安全预览可用；暂停凭证不能提交。视觉检查至少覆盖桌面 1280×720、窄屏及三种主题，并确认控件可用键盘操作。文档中的源码研究不能替代实际构建、原生加载和浏览器验证。
