# 质量运维：规则范围与执行

适用于插件 0.27.0、UI 13.0.0 和未修改的官方 CPA 8.0.76。完整的[上游功能与 CPA 适配对照](ACCOUNT_QUALITY_PARITY_CN.md)区分了题目检测、订阅状态探针和失败处置。

## 如何使用

1. 打开「质量运维」，在同一工作台查看概况、规则与运行记录。点击「新建规则」或规则上的「编辑」打开弹窗，依次填写名称、范围、模型、判题与计划。弹窗不分页，内容单独滚动，底部保持取消与保存。浅色、纯白和深色均跟随插件主题；提交时定位到第一个无效字段。
2. 新规则默认选中「全部已启用凭证」、`gpt-6-astra`、思考强度 `high`、每模型 1 份。点击快捷项、从凭证目录选取，或粘贴 ID（空格、换行、中英文逗号和分号均可）；回车或按加号生成可移除的模型标签。直接保存时也会包含输入框里尚未点添加的 ID。重复模型只算一次。动态范围不需选账号，按每个凭证注册的模型交集执行；选择「指定凭证」时须支持所有已选模型，不会回退到别的账号。
3. 在「判题设置」选择「题面与参考答案」，可就地展开固定题；随机题到执行时才生成。设定规则不显示预计探测次数，也不汇总样本。打开预览或保存规则都不会提交模型请求。仅在对全部已启用凭证点击「立即执行」时，确认框才按当时的目录估算主测调用量，不含判题与重试。没有匹配时不创建空任务，不消耗调用额度。
4. 点击规则名称可在右侧查看该规则全部保留历史，按 20 次运行翻页；清除筛选恢复全部规则。执行状态与样本质量判定分别展示。批次回执给出入队和跳过的凭证数。可从规则上的「最近批次」进入运行列表，按凭证查看这轮的模型、状态和结果。匹配数量不是成功数量，限额、状态变化都可能使实际执行数更小。回执未确认请先查运行记录，不要重复提交。
5. 「检测周期（五段 Cron，服务端时区）」只有一个文本框，默认 `*/30 * * * *`，即服务端每小时整点和半点。在「运行计划」打开唯一的「启用定时检测」并保存，只有本条规则从下个周期开始。新规则默认只允许手动执行，列表不再有总开关。未触碰开关时，原有手动、已暂停或定时状态均不改变。
6. 「保留检测结果数」默认 **100**，范围 **1–200**，同一规则内每个凭证单独计数。一个模型的一份主测样本记一条，失败而未取得样本的一次运行作为一条诊断保留；同批对照不另占一条。输入数少于一轮所需样本时，表单会提示并按一整轮保存。结果按最近的完成顺序保留，超限的旧样本在运行结束或后台清理时淘汰。未结束的任务和仍存在暂停归属的规则历史不清理。手动智商测试、审计和用量仍有独立的保留策略。

## 默认模型、快捷项与思考强度

- 上游[质量运营规则表单](https://github.com/ranxi2001/sub2api/blob/a71bcd6238777630bb74f18106097689ce7a5836/frontend/src/views/admin/AccountQualityView.vue)新建题目检测时仅选 `gpt-6-astra`、`high`、1 份；[快捷项组件](https://github.com/ranxi2001/sub2api/blob/a71bcd6238777630bb74f18106097689ce7a5836/frontend/src/components/admin/operations/QualityModelShortcuts.vue)提供 `gpt-6-astra`、`gpt-6.1-sol` 和 `gpt-5.6-sol`。它们是录入预设，并不表示 CPA 已经注册这些模型。目录为空仍可建动态规则，没有匹配则不产生请求。
- 「管理快捷项」可增删本地常用模型，删除快捷项不会从规则移除已选模型。上游按管理员 ID 存储；CPA 管理接口没有管理员 ID，因此插件偏好仅按本站点、此浏览器配置文件和插件路径保存，不使用账号或管理密钥作标识，也不随规则上传。存储不可用时退回本页使用。
- 题目检测的多个模型共用一个**请求档位**：`low`、`medium`、`high`、`xhigh`、`max`，默认 `high`。新表单直接展示全部五档，可用方向键选择。现行规则列表展示当前配置，运行记录展示当轮冻结值；二者都不代表上游实际生效档位。旧规则的 `minimal` 等已下线档位或未指定值显示「沿用原设置」。只改名称不会改档；主动换为新档并保存后，不能再选回 `minimal`。规则不再提供 Temperature 或按天保留输入。老规则的温度不会因改名而丢失；使用旧保留策略时，留下空白继续沿用，明确填写条数才改为按条数保留。
- 上游题目检测允许 50 个模型、100 个样本；其单模型限制是另一种订阅状态探针，不是题目检测。CPA 当前默认仍为每规则 8 个模型、每凭证 32 个样本，每模型 1–8 份。编辑器按实例实际的 `max_models`、`max_samples` 校验；需要达到上游规模时，可显式配置 50/100，不会自动修改预算。单凭证随机题带对照时主测与对照均计入样本限额；每日调用、token 以及队列限制仍独立生效。此改动不改变独立的「智商测试」或将基础设施错误记为质量失败。

当前布局的参考版本、交互与验证见 [质量运维工作台重构](QUALITY_WORKSPACE_13_0_CN.md)。

## 上游与适配

核对的 sub2api 源码版本为 `production` 分支的 `a71bcd6238777630bb74f18106097689ce7a5836`。上游[账号选择器](https://github.com/ranxi2001/sub2api/blob/a71bcd6238777630bb74f18106097689ce7a5836/frontend/src/components/admin/operations/QualityAccountSelector.vue)与[中文质量运营文案](https://github.com/ranxi2001/sub2api/blob/a71bcd6238777630bb74f18106097689ce7a5836/frontend/src/i18n/locales/zh/qualityOps.ts)区分手选与「所有匹配账户（含之后新增）」；[模板服务](https://github.com/ranxi2001/sub2api/blob/a71bcd6238777630bb74f18106097689ce7a5836/backend/internal/service/quality_rule_template.go)会把规则同步到匹配账户。这里对齐的是范围语义，不照搬上游的账户、分组或处置模型。

CPA 插件只存一条动态规则，在**每次手动或定时执行时**按当时目录展开。新增或重新启用的匹配凭证从下一轮起纳入，不加入已经入队的批次。旧规则缺少 `target_scope` 时仍按原 `auth_id` 执行。编辑已有规则不提交 token 字段时保留它原来的输出限额；普通表单不再要求填写。独立全局设置页已移除，但后台仍执行原有的并发、每日调用与 token 预算。

### 周期与历史兼容

普通题目检测对照上游表单的 `defaults()`、五段解析器 `scheduledTestCronParser` 和 `scheduled_test_results` 按计划保留的逻辑；订阅状态探针的两分钟默认值不适用于本页。五段依次为分、时、日、月、星期。例如 `0 9 * * *` 为服务端每天 09:00。本机 8317 使用 `Asia/Shanghai`；其它安装读取各自服务端时区，不跟随浏览器。下次运行以 UTC 保存，列表使用该次运行在计划时区的实际偏移（含夏令时）。

旧固定间隔或带显式时区的 Cron 默认只显示原计划。勾选「改用服务端 Cron」再保存才转换，取消编辑不改变计划；仅改名称不会推迟下次运行。管理 API 新建时省略 `cron`、`max_results` 分别使用 `*/30 * * * *`、100（至少覆盖一轮）；显式空或非法日期不回退。更新时省略计划或条数保留原值，不向新规则传 `interval_seconds`、`timezone`、`retention_days`。

## 准入与保护

- 已有客户端的实例级定时授权仍适用于旧计划。新表单只写本条规则的授权，不开启实例级许可。管理员通过原定时接口明确全部停止时，也会撤销逐条授权。随后启动一条规则不会补跑未执行的旧周期或唤醒其他规则。

- `host.auth.list`、`host.auth.models` 与 `host.auth.get_runtime` 交叉核对 ID、运行索引和提供商，只纳入可用且 `active` 的凭证。禁用、冷却、运行状态未确认、历史质量暂停、模型不匹配均跳过。某些仅写在配置中的 API Key 只有模型目录项，8.0.76 不提供可核验的运行状态；它们显示为未确认，不视为可用。
- 子任务固定到具体凭证和模型，每次采样前按该凭证索引复核，不扫描整个目录，也不回退到其他账号。公开接口没有与实际调用原子绑定的状态快照；最终路由仍由 CPA 决定。
- 一个批次只占一个队列位置。超过 1,024 个待完成的范围子任务，或已无队列空间时，整次提交失败，不会只运行前若干个；同一规则有排队或运行中的任务时不会再开一轮。被中断的任务重启后记为中断，不重放。
- 官方宿主没有独立质量暂停、释放或可信最终证据接口。观察结果不改变凭证，不用人工禁用模拟质量暂停。
