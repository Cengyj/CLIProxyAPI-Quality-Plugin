## 本次落地

### 自动重登执行前再次核对

自动登录任务可能先排队等待运行名额。在等待期间，管理员可能暂停或禁用凭证，CPA 也可能已恢复授权、进入冷却，或替换了账号身份。仅在入队时检查会让已经失效的任务继续使用密码和 TOTP 开始认证。

本次在取得运行名额后，再检查自动修复条件、异常证据和绑定身份。检查覆盖密码／TOTP 登录和授权码兑换两个取得名额的边界。条件变化的任务在相应调用前结束；未变化的任务正常继续。全局开关、账号开关和设置版本检查继续生效，提交前的最终检查也保留。已消费的回调不会因为任务停止而重新开放或自动重放。

### 导入和更新时校验 TOTP

当前浏览器运行时已经校验 TOTP，但旧保存入口主要检查非空和长度，错误密钥可能先入库、到登录时才失败。本次将相同规则提前到管理输入的共享解码边界，覆盖导入、更新、临时登录请求和资料库更新请求。

支持有效 Base32 或 `otpauth://totp`，限定 SHA-1、6 位、30 秒，检查重复参数、非法字符、长度与尾位；拒绝 HOTP 及不支持的参数。验证不改变用户保存的原始密钥文本，密码首尾空白保持。错误沿用固定 `invalid_credentials`，不把密钥内容放进报错。

参考项目为了兼容历史密钥会接受部分非标准 Base32 长度并丢弃尾位；当前插件运行时更严格，所以本次前移的是当前规则，没有改用参考项目的宽松算法。整批导入中存在非法项时整批不写；更新失败保留旧资料与版本。

## 验证范围

使用离线假账号、假授权和可控等待通道验证执行边界，不向 OpenAI 发起真实请求。40 组 TOTP 样例与现有 JavaScript 校验规则交叉核对；保存失败验证数据库和账号版本保持。13 个执行边界场景覆盖暂停、禁用、冷却、异常清除、身份变化、撤回同意、正常继续，以及授权码兑换停止后的单次消费约束。最终宿主测试、并发检查、编译、补丁复现、原生加载和安装证据集中于 `artifacts/tosub2-reference-7.0.0/`。

本轮不改 UI 排版、完整信息展示或登录运行包。已有 UI 与插件记录仅在输入 SHA-256 仍然一致时复用，发生变化的宿主与原生集成检查重新执行。
