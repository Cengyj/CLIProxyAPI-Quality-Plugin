# 0.3.0 设计与能力边界

## 当前产品规则

质量运维只保留一个自动动作：根据有效失败证据暂停整个凭证。**一旦暂停，不再自动复测，也不允许手动复测；仅管理员可以人工解除。** 解除之后相关检测规则仍停止，必须单独恢复规则才会开始新的检测。

手动测试不产生自动处置。默认观察模式；全局“定时检测”和“自动暂停”分别配置，规则也分别启用。安装、公共 GET、打开页面、保存题目配置或预设不调用模型。默认暂停门槛仍为连续三轮中所有选定模型都明确失败；本次不将一次答错直接解释为凭证异常。

完整旧逻辑复核与改造原因见 ARCHITECTURE_REVIEW_CN.md。

## 执行代码职责

- `engine.go`：实例所有权、存储加载、配置和关闭；原生入口用实例请求租约协调重配与停机。
- `admission.go`：服务端校验、依赖准入、参数冻结和先持久化后入队。
- `scheduler.go`：有界任务队列、可运行依赖预留、定时调度及后台维护。
- `execution.go`：固定凭证模型调用、取消、样本持久化和任务终态；`budget.go` 保存按 UTC 调用日期绑定的预算。
- `rules.go`、`transitions.go`、`reconcile.go`：证据决策、持久状态转换和宿主暂停对账。
- `queries.go`、`metrics.go`、`snapshots.go`：查询、指标和明确深复制；分页只复制当前页，持久数据读取失败会返回错误。

## 源码与边界

宿主来自用户提供的 `/Users/ceng/Downloads/CLIProxyAPI-8.0.67` 归档。该目录无 `.git`，8.0.67 是目录标签，源码构建版本默认 `dev`，不能推断上游提交。`host-patches/baseline.json` 保存 2,303 个白名单源码/构建文件 SHA-256；工作副本的首次 Git 提交仅是本地补丁基线。

插件是独立 `/v8` module，只依赖公共 SDK。宿主扩展位于 `workspaces/CLIProxyAPI/`，原目录只读。两个 module 分别测试与构建。插件显式重复 moego replace，因为依赖 module 的 replace 不向主 module 传递。sub2api 参考提交、许可证和未复用其源代码的说明见 SOURCE_AUDIT_CN.md。

## 两个权威域

宿主保存独立质量限制、持久身份 incarnation 和动作墓碑；插件保存检测规则、冻结条件、运行、预算、审计和预设。质量暂停不修改原生 Disabled、不清空冷却，也不编辑 auth 文件。有效不可用是人工禁用、质量暂停、原生冷却及其他限制的并集。

暂停动作绑定 auth_id、owner_plugin、rule_id/revision、action_id/revision、evidence_run_id、identity_version、原因和 UTC 时间。宿主核验真实 native 实例身份、所有权、版本与身份。质量库在凭证加载和服务放行前打开，失败阻止启动。插件停用、卸载或宿主重启不会静默释放暂停。

宿主能力 v2 不再提供质量暂停绕过。旧 quality_retest 请求和自动恢复回调明确拒绝。人工释放只允许来自有效的鉴权管理请求作用域；公共资源和后台任务不能借用该权限。插件不可用时，宿主保留管理鉴权的人工 CAS 释放入口。

## 规则状态和任务准入

- `detecting`：规则已启用，可显式执行；定时执行还需要规则与全局定时开关。
- `paused`：规则停止，无后续检测，等待管理员显式恢复。
- `awaiting_release`：持有暂停、存在暂停动作意图，或依赖凭证被暂停；只等待人工处理。

`enabled` 表示规则启用意图；`status` 是面向 UI 的状态。不能通过编辑 enabled 绕过权威凭证状态。规则暂停不释放凭证；人工释放不恢复规则。

任务的凭证依赖包括主体、随机题 control 和 LLM judge。暂停凭证时，所有相关规则停止，revision 增加、连续证据清零、NextRun 清空；依赖的排队任务被终止，插件正在执行的评测 operation 被取消。提交、取得依赖并发锁后，以及每次实际调用前均检查限制与任务版本。释放再启用规则也不会让旧排队任务恢复。

每凭证并发为1。调度器一次性预留运行所需的主体/control/judge，只有全部依赖可用才占用 worker；暂不可运行任务保持 queued，因此同一凭证的慢调用不会占满所有 worker。完成后释放预留并广播唤醒，不轮询或增加网络超时。已取消/阻断队列条目在容量检查前回收，保留其持久历史。全局 worker、队列与输出有界。

到期 tick 记录规则 revision，真正入队时再次验证该版本以及全局/规则定时开关。编辑规则或关闭调度会使已经捕获但尚未入队的旧 tick 失效；保存新配置不会因此触发一次意外检测。手动执行仍是独立入口。

## 证据与判定

execution_status、quality_verdict、action_status 分别保存。所有计划样本 completed、comparable 且可判定后，模型中出现 incorrect 才构成该模型失败。所有选定模型都明确失败才推进连续失败；unknown、缺样本、mixed 或条件变化打断连续。手动运行不进入动作决策。不存在连续通过计数、恢复门槛或自动解除分支。

每个样本固定真实 auth_id、provider 和模型，经 host.model 执行，复用正常映射、转换、thinking、代理与 payload rules。冻结题面、答案或人工标准、参数、预算、judge 模板、规则版本、身份和 payload 配置摘要。答案不会发送给被测模型。response_model 仅是上游返回值，不是模型身份认证。

最后一次模型调用结束后、执行规则动作之前，再检查主体、control、judge 的可用性和冻结身份；期间发生替换、暂停或人工禁用会使该轮不能形成新动作。连续证据签名包含主体、判题和对照身份，替换 judge 不继承旧失败计数。

目前最终条件观测覆盖原生 OpenAI-compatible chat/completions 的流和非流路径。观察发生于最终 payload 屏障之后且只读；题面/参数/预算改写、配置摘要不匹配、多次尝试或未核实路径均不可作为自动处置证据。其他供应商可在未暂停时手动观察，但不能自动暂停。

流式执行区分 HTTP SSE 与宿主 ABI 的裸 JSON 事件。兼容层会移除 [DONE]，因此必须结合宿主实际观察到的上游终止证明；回调 Done 或合成 finish 不足以证明完整。网络错误、401/403/429/5xx、拒答、空输出、截断、提前 EOF、取消和 judge 失败都不是答错。首包前、流中和非流式取消使用实例隔离 operation，不增加推理网络 deadline。

确定性题型只接受完整整数。LLM judge 可选且只调用一次，使用独立凭证，system 指令与不可信 JSON 数据分开，严格拒绝重复字段、非法值、额外字段、null 和额外输出。自定义标准与 prompt 一起冻结；确定性 parser 不猜测自定义题答案。人工评审独立保存，不修改自动证据。

随机题由本地有界求解器生成；seed=0 表示首次提交时生成非零 seed，冻结后可重现。同 run 的 control 必须同题、同映射、同参数、同 judge、同已知路径，并完整通过。宿主 comparison_identity 排除相同材料的别名；最新身份与冻结身份也需匹配。五分钟窗口仅约束证据，不转为上游超时。控制调用计入总样本与预算。

## 持久化和升级

插件 bbolt 使用 schema2。0.1.0 数据迁移保留历史、预算、预设、动作归属和审计，剥离自动恢复/复测参数的运行意义；未完成旧 run 标记 interrupted，不重发。暂停及待确认动作进入等待人工处理状态；恢复设置为 true 也不会产生模型调用或自动释放。

跨库不假称原子事务：先持久化暂停意图和相关检测停止状态，再调用宿主幂等暂停。对账读取 active/released/absent 和权威目标状态，核验归属绑定后修复记录并阻止依赖任务；没有模型执行分支。多个依赖暂停使用稳定标记，重复对账不改变版本。释放确认后仍停止规则；没有剩余质量限制时为 paused，否则继续 awaiting_release。人工释放先持久化停规则与新版本，再 CAS 删除匹配限制；仅释放自身限制，其他限制继续生效。

一个 data_dir 只允许一个实例持有。quiesce/shutdown 停止接单、取消 operation、等待原生请求租约与 worker 收尾后关闭数据库。开始关闭或持久化故障后，写操作统一拒绝；并发重复 Close 等待首次关闭完成并获得相同结果。重启保留已完成样本，不重发无法证明完成的网络请求。固定间隔和五段 cron 使用 IANA 时区，UTC 存储。

## 预算、保留和指标

逐次调用先持久化调用数与输出 token 上限预留，再结合已知 total token 保守阻止后续调用。未知 usage 单独计数，不伪造零成本。输入 token 事前不能精确估计，单次已发起调用可能超过剩余额度，后续调用被阻止。

每次主体、control、judge 调用分别绑定准入时的 UTC 日期。跨午夜才返回的用量仍写原日账本，不消耗新一天的预算。`meta/budget:YYYY-MM-DD` 保存每日账本，`meta/budget` 保留当前兼容快照；旧快照在首次切日时自动归档，无需更改 schema。历史随 retention_days 清理，仍有在途调用的日期不删除。token 累计饱和保护避免整数溢出绕过预算。

存储阈值是新任务/规则准入阈值；已有有界任务仍能写终态和动作记录，不等同文件系统硬配额。按规则/全局保留期清理历史，持有动作依据、规则最近结果和动作墓碑按保护规则保留。

被动 usage 回调仅向256条有界缓冲写入脱敏元数据，后台落库，丢事件可见。可信 TrafficSource 来自宿主 context，缺失归 unknown；旧 Source、APIKey、Cookie、token、生产提示词与回答不落盘。事件是执行尝试，不等于入站请求。质量率使用 correct/(correct+incorrect)，覆盖率使用可判定/计划样本，judge 与 control 用量另列。

## 明确限制

Home 动作不支持；没有对应控制平面接口时不绕过。当前实际平台验收为 macOS arm64；其他平台需独立重建和验证。

暂停以宿主最终传输准入为边界：准备中刚被暂停的执行不能再提交，已经通过最终准入的业务传输可自然完成。无法将本地状态变更与远端接收组成原子事务。

持久身份不用全局 Generation、进程内 epoch 或 inode/mtime 猜测。已观察到的删除重建、材料变更和正常刷新有明确语义；但宿主停机期间删除文件后用完全相同材料重建，现有身份 API 无法识别该文件操作。此类离线维护需要显式处理旧归属并通过受管理流程建立新身份，不能把旧证据当新导入证明。
