# Credential Ops 0.29.36 验证

插件英文名改为 **Credential Ops**，仓库为 [Cengyj/cpa-credential-ops](https://github.com/Cengyj/cpa-credential-ops)。UI 为 13.6.35，内嵌 Go/Sobek 运行时仍为 2.2.1。插件 ID、动态库文件名、管理路由与数据目录保留 `model-quality`，既有账号、凭证绑定、规则及历史无需迁移。

## 检测范围与处置

指定凭证、全部已启用、全部凭证三种范围遵循相同处理原则。已启用凭证的 CPA `error`、不可用或冷却状态不再直接排除检测。实际调用返回的 401、402、额度耗尽 429 和模型不支持 400/404 进入各自配置的处置；历史状态文字不作为本轮处罚依据。

可信非空目录已明确缺少所选模型时，保存 `completed` 运行及 `preflight_detail`，显示目录依据和实际处理结果，回答数组为空。目录为空或无法读取时继续按所选模型核实，不凭缺失信息认定无模型。目录检查不伪造成上游 HTTP 400，也不计入答题质量通过率。

错误规则成功停用后，处置记录成为本地终止条件。后续立即执行、定时、其他规则和重启均不再按该凭证读取状态或快照、答题、重复写入，也不创建新的跳过记录。轮末凭证存在性核对同样排除它。旧错误停用记录在启动时从已有证据补齐来源，不向 CPA 发起重新检测。

普通答错暂停仍使用原有可选恢复配置；人工禁用的复检特例、历史独立质量暂停、身份冲突、未知写入不重放继续受保护。

## 验证覆盖

- 完整插件模块测试、`go vet` 和完整模块竞态检查。
- 三种范围下，运行异常与冷却凭证实际进入管理探测；旧状态显示 401 而本轮答题成功时，不误处罚。
- 目录缺模型与目录未知分开处理，固定规则和动态规则保留全部所选模型。
- 六种错误来源成功停用后的连续轮次和重启：零新增凭证检测记录、零模型调用、零重复处置；Go 用例同时验证目标级状态读取为零。
- 排队等待读取槽期间，另一任务已完成错误停用时，不再开始该凭证的状态读取。
- 隔离官方 CPA 原生加载、重启、鉴权、六项静态资源校验，以及桌面和手机详情/范围预览/导出回归。

本地验证材料位于 `artifacts/scope-policy-0.29.36/`，该目录不进入源码发布。真实实例只沿用用户授权的现有定时任务；开发测试使用合成凭证和假上游。
