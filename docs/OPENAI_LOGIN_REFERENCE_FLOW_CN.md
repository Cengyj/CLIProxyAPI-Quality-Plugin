## 本次实现

按 `/Users/ceng/Downloads/toSub2-go-port/internal/protocol/flow.go` 的现有账号登录顺序重新实现默认流程。每次任务创建一个浏览器上下文，全部步骤使用同一个代理与 Cookie：

1. 打开 ChatGPT 首页，读取 providers 与 CSRF，提交官方网页登录入口。
2. 跟随到密码页，用当前官方 Sentinel SDK 生成本次步骤信息，提交密码。
3. 从真实响应中读取 TOTP 因子，创建 challenge，生成当前六位验证码并提交。仅有 HTTP 200 不构成成功，必须有明确下一步。
4. 完成官方 ChatGPT 回调，并读取会话确认邮箱与当前账号一致。
5. 在同一上下文打开 CPA 已生成的 Codex OAuth URL，保持宿主的 PKCE、state、client ID 和回调地址。
6. 核对账号会话与工作区，截获最终回环回调，交给 CPA 兑换授权、核验身份和生成候选。

新实现位于 `login-runtime/reference-flow.mjs`，由 `core.mjs` 负责浏览器、来源/路径限制、取消和超时。`worker.mjs` 默认使用新流程。旧直接 OAuth 表单流程仅供内部回归夹具使用，管理接口和 worker 输入不能切换到它。

这里参考的是账号协议和状态推进，不宣称完整移植了目标项目的 Go 引擎。官方 JavaScript、Sentinel、Cookie 和网络由真实 Chromium 执行，没有复制 Sobek 模拟环境、TLS 指纹组件、网站挑战求解器、账户注册、密码重置或 MFA 设置代码。代码来源和参考文件摘要记录于 `login-runtime/SOURCE_MANIFEST.json`。

## 成功、失败与人工步骤

密码和 TOTP 每个任务最多提交一次。明确凭证拒绝、普通权限错误、限流、服务错误、网站验证分别分类；不根据任意 400/403 判断密码或 TOTP 错误。官方 SDK 返回缺字段或带错误的结果时，在提交密码前停止。

邮箱验证码、电话验证、账户资料完善与人工网站验证是独立的停止状态。自动网站检查可以等待官方页面完成；仍需人工操作时不宣称登录成功。

网页登录身份必须与账号邮箱一致。已有账号重新授权必须选择宿主绑定的工作区；首次导入只有一个明确工作区时可继续，多工作区不会静默选第一个。OAuth 会话支持匹配邮箱按钮与唯一合法隐藏 session 输入。按钮提交等待明确导航，不按固定短间隔重复点击。最终 callback 优先于响应中的旧工作区列表，防止重复选择。

运行时只交回 callback，不兑换 token，也不写凭证。候选核对与提交继续沿用 CPA 的鉴权接口；新凭证默认禁用，已有人工禁用、质量暂停、冷却和停止规则保留。

## 实时阶段日志

1.2.0 的 stdout 使用 NDJSON：固定进度事件与一个最终结果。进度仅包含 version、type、job_id、attempt、phase。允许阶段包括准备环境、建立网页登录会话、邮箱、密码、TOTP、网站验证、OAuth、授权确认、工作区和回调。

宿主每收到合法阶段即持久化，UI 原位轮询展示。单行上限 12 KiB、累计 64 KiB、最多 64 条进度；身份不匹配、未知字段、重复最终结果或最终结果后的输出都会拒绝。旧 1.0/1.1 运行包仍兼容单 JSON 协议。取消或任务结束后，迟到进度不能恢复任务。

密码、验证码、Cookie、SDK token、授权 URL 和 callback 参数不写进进度日志。账号资料仍按用户要求明文保存，持久化位置没有改变。

## 验证

离线双源夹具实际启动 Chromium，验证网页登录、密码、TOTP、原宿主 OAuth、同一认证代理、Cookie 连续性与回环回调不外发。额外覆盖响应缺 continuation、未知成功、SDK 错误、网站验证与普通 403 区分、隐藏 session、延迟授权、取消和多工作区。

宿主验证覆盖流式 IPC、实时日志持久化、迟到进度、旧协议兼容和并发取消。UI 验证覆盖新增阶段、原因、轮询更新与账号目录功能。最终记录和真实账号尝试结果分别保存在 `artifacts/login-reference-1.2.0/verification-final/`、`real-login-result.json`；离线通过不代表真实账号已经登录成功。
