# 一次点击完成 2FA、保存与启用

插件 0.14.0 / UI 9.1.0 将账号列表的“2FA 登录”“重新登录”变为完整操作：点击一次，Go＋Sobek 完成密码/TOTP 和 OAuth 授权后，插件自动写入 CPA 并启用凭证，最后在原账号行显示结果。无需转到登录任务页核对候选，也无需另开 CPA 页面启用凭证。

本次点击包含保存和启用授权。新任务的 `auto_commit`、`enable_credential` 固定在创建时，不能在任务完成后由页面随意改变。账号设置已授权的巡检重登采用相同自动保存流程，但人工禁用或冷却中的目标不会发起后台修复。

## 页面行为

- 登录进度、保存进度、完成结果均留在当前账号行；筛选和列表位置不因成功而改变。
- 成功后刷新账号绑定及凭证数据，不再发起第二个 `/commit` 请求。
- 只有 CPA 返回的凭证身份和启用状态核对通过后，显示“已保存并启用”。这个结果不代表已经执行模型推理测试。
- 保存结果不确定、启用冲突或身份变化会显示错误；不会自动反复登录、导入或覆盖。
- 显式手工 OAuth 和历史待确认候选保持原单次提交入口；不会因打开页面、刷新或升级自动消耗旧候选。

## 写入边界

插件仍仅使用官方公开回调，无 CPA 源码改动。保存前复查目标身份、完整策略指纹、当前任务及自动化许可；账号登录按授权将 `disabled` 写为 `false`，其他策略字段保持原值。用户手动登录可启用在启动时已知的禁用凭证，但任务开始之后发生的禁用或其他策略修改会使快照失效。历史质量暂停仍阻止提交。

保存前持久化收据，最多写入一次；保存后核对物理文件与运行时 ID、索引、提供方及禁用状态。不一致时保留 `commit_unknown` / `saved_not_adopted`，重启不重放。官方回调没有跨进程原子 CAS，因此不承诺其他管理器并发修改下的原子覆盖。

## 验证与当前实例

验证使用假账号、假授权交换和本地假上游，不发起真实 OpenAI 登录。UI 报告位于 `artifacts/login-oneclick-0.14.0/`，包括账号页 53 项和登录页 17 项检查及桌面/手机截图。

8317 已在用户确认后切换为官方 CPA 和插件 0.14.0 / UI 9.1.0。2 个账号、其中 1 个已绑定及 9 条登录记录均已保留，旧绑定已完成身份核验转换。没有进行真实登录或模型调用。详见 [本机升级记录](LOCAL_OFFICIAL_UPGRADE_CN.md)。

该次升级包含以下一次性处理，其他旧实例不能只替换动态库：旧账号库由宿主保存，新库由插件保存；已绑定账号的身份版本算法不同，需要一次经过身份核对的转换。另外旧登录运行包位于 auth-dir 的子目录，官方凭证加载器会递归读取其中的辅助 JSON，必须将整个旧登录目录可逆移出凭证扫描目录。新版安装包本身不自动迁移或清空旧数据。
