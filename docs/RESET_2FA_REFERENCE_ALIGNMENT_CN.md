## 对齐结果

| 环节 | 原插件 | 本次实现 |
| --- | --- | --- |
| 初始状态 | 必须恰好有一个普通旧因子 | 有旧因子时核对绑定；无旧因子或合规缺失元数据时直接登记；多因子、恢复因子、矛盾数据不授权移除 |
| 状态查询 | 部分路径固定三次 | 同一内存会话最多四次只读查询，暂态失败可重试，认证拒绝立即停止；可信修改回执不额外查询 |
| 初次登记冲突 | 不支持 | 仅明确的 already-enrolled 业务拒绝允许复查；复查明确未启用则再登记一次；有因子则必须匹配独立保存或本轮登录验证的绑定。移除旧因子后的首次登记若明确冲突，也仅在复查已禁用时再登记一次。总计最多两次登记，不再次移除，不追逐新出现的因子 |
| 旧因子移除 | 使用当前列表唯一值 | 同时检查已保存绑定和本次登录证明；固定一个目标，确认移除才继续 |
| 激活证据 | 要求状态查询列表仅含一个因子 | 先拒绝跨账号回显、互相矛盾的成功信号及不合规字段；完整可信回执直接进入本地提交；回执不明时只读核对本次登记因子，允许与其他正常因子共存，重复或错误 ID 不成立 |
| 本地保存 | helper 结束后再写账号资料 | 先私有日志落盘、同步、读回，确认依据绑定操作、账号、密钥、登记会话和因子摘要，再通过专用 IPC 等待父插件事务写入账号、因子 ID、同账号凭据副本和任务结果；读回一致后才确认继续 |
| 保存失败/重启 | 可在结束对账中直接补保存 | 新版未确认的本地提交保持隔离，由“仅完成本地保存”显式处理；不初始化网络、不登录、不查询、不激活、不退出、不授权、不上传 |
| 普通登录 | 选择第一个 TOTP 因子 | 使用已保存因子；没有绑定时只接受唯一普通因子，验证码通过后保存绑定；多因子不试码 |
| 退出设备 | 文案宣称全部退出 | 完整有效的 2xx 表示服务器接受请求；不推断所有会话即时失效。失败或不明阻止后续授权 |
| 重试与敏感资料 | 未确认修改隔离 | 保留隔离；只允许传输层证明 HTTP 从未发送的连接重试。未确认密钥保留在私有证据中，不通过账号资料当作有效密钥显示 |

## 与插件架构的对应

保留用户先前指定的两个开关：退出所有设备、重新授权 CPA。后者继续包含新会话登录、授权、上传；不增加参考应用的 Sub2API 目标或其他登录方式。已排除套餐的 CPA 上传政策、身份核验、人工禁用与历史质量暂停限制继续生效。

插件继续使用已获批准的明文私有账号存储策略，不迁移成参考应用的 Linux 外部密钥加密存储。持久化采用插件现有 bbolt 事务和私有操作日志；其证据版本是插件 schema 3，不冒称与参考应用日志文件格式通用。旧 schema 1/2 只按原有严格证据校验读取，缺失的新字段不补猜，不改写历史日志。

新密钥被确认激活，不等于全部其他验证器失效。仅明确选择的旧因子具有移除证据。退出成功字段 `devices_logged_out` 为兼容 API 保留，界面解释为“退出请求已接受”。

## 验证方式

使用假上游请求账本覆盖无旧因子、已绑定旧因子、缺失元数据、冲突后已禁用、冲突后匹配绑定、错误/无绑定、二次冲突、未知响应、并存因子和重复 ID。另验证父子进程确认管道、账号/凭据/任务保存顺序、重启隔离、纯本地完成零运行时调用、历史证据字节不变、以及后续失败时保留新密钥。

不执行真实账号登录、重置、退出或模型请求。构建后在无外网的临时 CPA 中检查加载、鉴权、资源哈希、嵌入运行时和重启；线上只检查安装版本与合成数据界面。
