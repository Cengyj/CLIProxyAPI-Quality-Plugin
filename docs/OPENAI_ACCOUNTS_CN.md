# OpenAI 账号管理与定时巡检

> UI 8.9.0 更新：临时登录入口及表单已移除，账号列表不再显示登录出口列。代理继续通过账号资料、批次导入和“代理与巡检”配置。下面涉及旧临时登录流程的内容仅保留为历史说明，已有保存资料不会因移除界面而删除。

插件 0.7.0 / UI 8.1.0 将独立“OpenAI 登录”页面划分为“账号管理 / 临时登录 / 登录任务 / 巡检设置”。账号管理保存可重复使用的登录资料；临时登录保留原有浏览器授权和单次密码/TOTP流程。安装或打开页面不会自动登录，巡检和自动重新授权默认关闭。

## 导入与首次登录

1. 在“账号管理”点击“导入账号”，无需初始化加密资料库。
2. 点击“导入账号”，每行使用 `邮箱----密码----2FA长期密钥`，一次最多100条，总计最多1000条。使用首尾分隔符，密码中的空格和中间的 `----` 原样保留；2FA不是六位动态验证码。重复账号或任意无效行会拒绝整批导入。
3. 导入只保存加密资料，不发起登录。列表显示完整邮箱、关联的 CPA 凭证、最近登录/巡检状态与时间。
4. 点击账号的“2FA 登录”，选择导入新凭证或明确选择已有 CPA 凭证。不会仅按邮箱静默绑定。
5. 首次授权成功后进入候选确认，检查身份和目标再提交。新凭证默认禁用；更新已有凭证保留人工禁用、质量暂停、冷却等限制。登录任务可以从独立“登录任务”查看。

删除账号只删除本机保存的登录资料和自动化设置，不删除 CPA 凭证，不撤销 OpenAI 授权。旧版临时登录资料库不会自动迁入账号管理，需要重新导入并完成明确的授权绑定。

## 巡检与自动重新授权

“立即巡检”读取 CPA 已记录的凭证状态，不调用模型、不访问远端健康探针，也不启动自动登录。没有观察到认证错误只能表示“尚未观察到异常”，不能保证远端账号正常。

定时巡检默认间隔15分钟，可设为5–1440分钟。保存后由宿主调度，关闭页面后继续运行；宿主重启会恢复已保存的设置。修改输入不会立即生效，须点击保存。

自动重新授权必须同时满足：

- 全局“定时巡检”和“自动重新授权”均已启用。
- 该账号已完成可信授权绑定，并单独允许自动重登。
- CPA 记录了凭证级明确认证失效，例如需要重新登录、凭证级401或终态失效授权。
- 绑定的稳定身份未改变，凭证支持更新，且没有人工禁用、质量暂停、原生冷却、正在刷新或未决提交。

普通网络故障、通用403、额度429和单个模型错误不会触发自动重登。只有满足上述条件的已绑定账号才会自动完成密码/TOTP授权及同身份凭证更新；首次导入和手动登录仍需候选确认。提交前会再次检查账号授权开关、凭证身份、政策状态和同一份失效证据。开关关闭会阻止尚未提交的自动任务继续提交。

自动任务在密码／TOTP 登录与授权码兑换分别取得执行名额后，也会重新核对同意开关、身份和异常证据。排队期间已暂停、禁用、进入冷却、恢复或改变身份的凭证不会继续进入相应认证步骤。导入和更新资料时前置验证 TOTP 格式，失败保留原资料；具体对照与验证见 [toSub2 Go 逻辑对照](TOSUB2_GO_REFERENCE_CN.md)。

临时执行失败最多尝试3次，后续尝试至少间隔1小时、2小时，实际启动受巡检周期约束。密码/TOTP错误、交互挑战、身份变化或提交结果不确定会转为待处理，不进行循环重登。成功更新后不会因同一份旧错误重复授权。普通 CPA token 刷新仍由原机制负责。

这属于认证维修，不是质量恢复：不会释放质量暂停、恢复检测规则或清空冷却；自动流程会跳过质量暂停账号。管理员显式进行的认证维修也不能作为解除质量暂停的证据。

## 管理 API

统一前缀 `/v8/management/credential-logins`，使用现有 v8 管理鉴权。所有写入要求 `Idempotency-Key`；拒绝未知字段、重复JSON键和写请求query，响应不缓存。

| 方法与路径 | 行为 |
| --- | --- |
| GET `/accounts` | 完整邮箱及状态的账号列表 |
| GET `/accounts/detail?id=...` | 管理账号时读取完整邮箱、密码和2FA密钥 |
| POST `/accounts/import` | `{entries:[{email,password,totp_secret}]}` 原子批量导入 |
| PUT `/accounts/entry` | 按 `id,revision` 更新备注、账号自动化开关或同邮箱登录资料 |
| DELETE `/accounts/entry` | 按 `id,revision` 删除本地账号记录 |
| POST `/accounts/start` | 按 `id,revision` 手动登录，可明确指定 `target_auth_id` |
| POST `/accounts/inspect` | 只读巡检全部账号或指定 `id` |
| GET/PUT `/accounts/settings` | `revision,inspection_enabled,auto_relogin_enabled,interval_minutes` |

批量导入请求上限512 KiB；其他登录写请求上限16 KiB。账号 revision 用于防止并发覆盖；冲突后先刷新。任务记录增加 `account_id` 和 `automatic`，用于追踪来源。账号列表返回完整邮箱；密码与TOTP密钥仅在打开“账号资料”时由受管理鉴权保护的详情接口读取。UI显示完整值，无星号遮盖。详情与其他响应不缓存，切换面板/页面或断开连接会清除资料输入，不写浏览器存储；token不属于该资料接口。

## 存储与验证边界

账号、密码和 TOTP 长期密钥明文存入宿主 `<AuthDir>/.credential-login/credential-login.db` 的 `accounts` 桶（bbolt / gob，schema 2）。无需初始化，不再创建或依赖 `vault.key`。备注、绑定、许可、巡检设置、失败计数与下一次执行时间一并持久化。当前尚未上线，不实现旧加密数据库迁移；旧开发库由管理员确认无数据后备份重建。详细路径与恢复方式见 [持久化说明](PERSISTENCE_CN.md)。

账号管理复用已有登录运行包；本轮未变更固定OAuth地址、运行包协议或网页登录实现。开发和验收使用离线假账号与假认证服务，不使用真实 OpenAI 登录、不调用真实模型。真实网站风控、验证码挑战及未来页面变化仍需实际运行时处理；遇到挑战会停止并要求人工处理。

账号管理首版验证和安装记录集中于 `artifacts/account-manager-6.0.0/`，当前 UI 8.0.0 证据位于 `artifacts/login-content-8.0.0/`。原登录机制与运行包详见 [登录实现](OPENAI_2FA_IMPLEMENTATION_CN.md) 和 [运行包说明](OPENAI_2FA_RUNTIME_CN.md)。
