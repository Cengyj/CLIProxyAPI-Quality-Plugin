## 导航与任务排版

主导航顺序改为“账号管理 → 智商测试 → 质量观察”。没有 hash 或 hash 无效时默认打开账号管理；明确的 `#manual` 和 `#operations` 链接仍进入对应页面。

登录任务使用 288px 桌面历史侧栏，按操作／时间、账号、结果分层展示。搜索覆盖账号、任务和错误代码，可组合“全部／进行中／需关注”筛选；超过全局最近 200 条时明确显示范围。历史卡片按内容高度排列，避免大量任务挤压重叠。窄屏将历史列表放到详情上方并限制其滚动高度。

详情区用小型状态图标、结果标题和紧凑元信息呈现当前任务；重置 2FA、退出设备和重新授权以横向步骤及箭头展示，只有已确认事实才标为完成。删除重复成功提示及大块留白，保留必要的未知结果处理说明。账号表格、操作按钮和 toSub2 套餐配色沿用现有设计。

## 直接可见的执行日志

执行日志直接位于任务结果下方，不再只在通用“排障信息”中显示任务编号。任务和账号行内日志共用事件布局：毫秒时间、与上一条事件的间隔、级别、中文阶段／原因，以及请求的方法、HTTP 状态和耗时。每条可展开查看固定字段和转义后的 JSON。搜索支持中文、阶段、错误码及请求类型，并可与异常筛选组合。

记录跨度只是首尾已读取事件的时间差；相邻间隔不是阶段耗时。新增 `duration_ms` 才表示对应协议请求的耗时。单次请求出现 HTTP 4xx／5xx 或传输失败不会被界面等同为整个任务的最终结果。轮询保留已挂载的日志面板、搜索内容、展开状态和阅读位置；跟随最新可显式开启。

“复制诊断”“导出 JSON”和“导出当前任务”均包含所选任务的全部已读取事件，不受当前搜索或异常筛选影响。报告 schema 2 保留界面／运行时版本、生成时间与时区、任务编号、诊断字段、任务与日志版本、保留范围及完整性信息。读取失败或版本不同步会明确标记，不能冒充完整同步记录。字段与类型白名单排除邮箱、凭证身份、密码、2FA 密钥、令牌、代理地址、URL 和响应正文。

## 新任务的后端诊断

| 诊断内容 | 用途与边界 |
| --- | --- |
| `event`、`revision`、事件序号与时间 | 区分状态、请求和明细上限事件；关联任务快照 |
| `request_kind`、`method`、`http_status`、`duration_ms`、`failed` | 固定端点代号、请求方法／状态／耗时和传输失败，不记录请求 URL、头或正文 |
| `runtime_code`、`error_stage`、`error_reason` | 保留受控运行时错误、超时前最后阶段与固定网络／响应诊断 |
| `security_status`、`totp_reset`、`devices_logged_out`、`credential_enabled` | 只记录事件当时已确认的结果，不把最终状态倒灌到历史事件 |

运行时请求通过绑定任务编号与 attempt 的 IPC 传入插件，使用闭合集合校验后与任务状态在同一事务中保存。OAuth 授权码兑换错误保留数值 HTTP 状态和固定原因；一次性授权码仍不重复交换。安全操作结果不确定时仍隔离并禁止重放，同时保留此前诊断。

每个任务保留最近 **200 条事件**；最多记录 **128 条协议请求明细**，达到后写入明确标记，继续保存阶段变化与最终结果。终态任务保留 **30 天**。开头截断、历史记录缺失、请求明细上限和读取未完成分别说明。请求日志覆盖协议层登录／安全调用，不包含原始 Sobek challenge 内部请求。旧任务与既有事件不重写，也不能补回过去未记录的诊断。
