# Model Quality task workspaces

Mode: Operate. Audience: a self-hosted CPA administrator. Scope: complete replacement of plugin/ui while preserving APIs and execution/security semantics. The user delegated design decisions and explicitly requested implementation without another layout approval round. Code-led implementation; no comp approval is needed.

## Direction contract

THESIS: A task has its own working surface: configure, then read evidence. Operations foreground owned restrictions, then rules and audit. The previous persistent form/results split and ornamental navigation are removed.

OWN-WORLD: CPA warm neutrals, warm black, white working surfaces, compact system sans, restrained red/amber/green for named states. Flat section boundaries, firm warm-gray primary buttons and clear focus rings. Administrators work in both daytime and dim evening conditions, so warm light, white and warm dark are supported.

STORY: Choose exact conditions, intentionally execute, compare each model's same-numbered sample, inspect proof, and record a review. Separately inspect restriction ownership, preview a bounded release, reconcile the result, and explicitly resume a rule if appropriate.

FIRST VIEWPORT: A 72px top navigation, slim data freshness line, a task heading and local view switch. New evaluation uses three named field groups and a inline submit summary. Once submitted, the form gives way to status, frozen conditions, model/sample selectors and two aligned answer columns. Operations opens with pending owned pauses and credential restrictions, with statistical definitions below. Signature interaction: aligned sample comparison while frozen conditions remain a single disclosure away. Motion only follows progress and state feedback.

## Function / state / action / feedback

| Function | States | Action | Feedback |
| --- | --- | --- | --- |
| Connection | disconnected, reading, connected, stale, 401 | connect, refresh, disconnect | memory-only key; stale data blocks execution; 401 clears session |
| Evaluation setup | empty, valid, blocked dependencies | choose target/models/question; preset; advanced parameters | call count; exact target; no calls until explicit submit |
| Task | queued, running, terminal, query error | cancel, retry progress query, history, eligible rerun, export | separate execution status, verdict and action; recover polling without resubmit |
| Evidence | comparable, insufficient, unknown, incorrect | compare model/sample, inspect frozen fields, copy, sandbox preview, review | missing values stay unknown; raw JSON secondary |
| Rules | observing, scheduling, disabled, awaiting release | save, explicit run, pause/resume, edit/delete | global vs rule permission; valid failure rounds; save does not execute |
| Restrictions | own pause, other owner, manual disable, native cooldown, unavailable | inspect owner and action version; preview matching release | whole credential scope; no paused retest in target/control/judge |
| Release | preview, committing, conflict, uncertain, reconciled | confirm bounded release; refresh authoritative state | rules stay stopped, old counters reset, remaining restrictions visible |
| Metrics/audit | known, unknown, empty, failed read | view definitions and events | pass rate and coverage denominators; missing usage is unknown |
